## 1. Proof devices

| Technique | How to use it | Cards |
|---|---|---|
| **Two-counter complexity count** | Bound successful iterations by a step-size floor (while not ε-stationary) plus telescoped sufficient decrease; bound unsuccessful ones by taking logs of the product of expansion and contraction factors; add the two. | [S023 pp. 5–6; S034 pp. 9–10; S046 pp. 10–11; S074 pp. 14–16; S060 pp. 10–12; S032 pp. 7–10; S045 pp. 10–11; S110 pp. 7–9] |
| **Split the n-dependence** | Write the evaluation bound as (poll size) × cm(D)⁻² so each factor n has a named source; then optimize the ratio \|D\|/cm(D)² over designs to ask whether the n-order is optimal *within that template*. | [S023 pp. 7–8; S041 pp. 2, 4–5] |
| **Borrow a lower bound by reduction** | Show your method *is* a classical method in dimension 1 (direct search with {−1, 1} = steepest descent with a Goldstein–Armijo search) and inherit that method's lower-bound example for the ε-order. | [S023 p. 8] |
| **Model / Oracle / ε-solution box** | State the problem class in Nesterov's three-line format so the algorithm bound reads as an upper complexity bound for a class. | [S023 p. 2] |
| **Exponent balancing** | When a design parameter has a free exponent (ρ = ctᵖ, a schedule power), choose it by minimizing the ε-power of the bound, then check it against past numerics; it can be posed as a small LP. | [S023 p. 7; S034 p. 10; S032 p. 15; S107 pp. 10–11] |
| **Step size → 0** | Get lim inf α_k = 0 by lattice finiteness (mesh methods), by summability of forcing-function decreases (sufficient decrease), or by a packing argument in objective space (list methods: each success removes a ρ*-hypercube). | Lattice [S005 p. 10; S003 p. 30; S083 p. 6]; summability [S049 p. 7; S050 pp. 6–7; S057 p. 5; S073 pp. 10–11; S014 pp. 8–9; S071 pp. 9–10]; packing [S003 pp. 30–31; S007 p. 17] |
| **Refining-direction Clarke stationarity** | At unsuccessful iterations along a refining subsequence, add and subtract the forcing term, normalize by the step, and pass to the Clarke derivative; density of refining directions gives full stationarity. | [S003 p. 13; S024 pp. 11–13; S049 pp. 8–11; S050 p. 8; S057 pp. 6–7; S067 pp. 12–14; S073 pp. 11–12; S088 pp. 12–13] |
| **Pigeonhole a varying witness** | When the index that fails (objective j(k), piece, mode) changes with k, pass to a subsequence on which it is constant over a finite index set. | [S003 p. 13] |
| **Chain back to the last success** | If the acceptance test compares quantities from different iterations (worst offspring vs previous worst), freeze them during unsuccessful iterations and chain back to the last success to recover a standard "no sufficient decrease at x_k along d" inequality. | [S050 pp. 9–10] |
| **Unify both globalizations in one proof** | Write ρ̄ ∈ {0, forcing function} in one algorithm box and apply it to the displacement, ρ̄(α_k‖d_k‖), so integer-lattice (simple decrease) and sufficient-decrease variants share one stationarity proof. | [S024 p. 6, footnote p. 12; S003 pp. 4, 28–31] |
| **Bridge inequality into a classical theorem** | Prove one inequality that puts the new step into the form a known theorem needs (Powell's Cauchy bound, Nesterov's template, Dennis–Moré), then reuse the rest of the proof lemma by lemma. | [S037 pp. 6–7; S081 pp. 4–5; S039 pp. 6–7; S046 pp. 4, 7–9; S084 pp. 7–10; S085 pp. 9–10; S077 pp. 18–21; S042 p. 18; S043 p. 10] |
| **Transplant across families** | Map roles between companion methods (radius ↔ step size, ‖S_k‖ ≥ ρΔ_k) and run the direct-search proof inside a trust-region method, or vice versa. | [S027 pp. 6–8; S071 pp. 2–3, 9–11; S067 pp. 15–17] |
| **Collapse check** | State a corollary showing that the new theorem reduces to the known one when the new object is trivial (m = 1 objective, exact values, no bounds). | [S003 p. 14; S013 pp. 1–2; S011 p. 2; S111 p. 5; S019 p. 12] |
| **Absorb inexactness** | Shift the acceptance threshold (η₁ → η₁ + ξ₀), treat inexact computations as exact ones on a perturbed operator or problem, or require inexact values within a fraction of the predicted decrease. | [S013 p. 14; S040 pp. 139–141; S090 p. 22; S047 pp. 5–6; S062 pp. 8–9; S044 p. 7] |
| **Log step size as a random walk** | Write Σ[Z_k ln γ + (1−Z_k) ln θ]; with success probability above p₀ = ln θ / ln(γ⁻¹θ) it is a submartingale with bounded increments, which gives almost-sure convergence. | [S014 pp. 10–11; S019 pp. 8–9; S043 pp. 9–11; S045 pp. 13–14] |
| **Two-layer probabilistic proof** | (i) A deterministic lemma, valid for every realization, bounds how many *good* iterations can happen before ε-stationarity; (ii) a conditional Chernoff bound on the number of good iterations turns it into a high-probability complexity bound. | [S019 pp. 11–13, 22–24; S027 pp. 6–9; S045 pp. 13–14] |
| **Potential with capped false-acceptance loss** | Use Φ_k = f(X_k) − f* + ηΔ_k^q; write the true decrease as (θ − Z_k)Δ_k^q so a false success needs an estimate error ≥ Z_kΔ_k^q, and bound its expected loss by the tail bound; successes and failures then fit one inequality. | [S067 pp. 11–12; S102 pp. 11–13; S110 pp. 16–18] |
| **Renewal–reward with arbitrary p** | When the per-iteration success probability is below 1/2, bound the expected hitting time by requiring positive drift of the log step size, p log γ + (1 − p) log θ > 0. | [S102 pp. 16, 22–25; S110 p. 13] |
| **Half-step σ-algebra** | Condition on F_{k+1/2}, which contains the random direction but not the accept/reject outcome, to handle the two sources of randomness in separate steps. | [S102 pp. 11–14; S110 pp. 15–16] |
| **Borel–Cantelli on summable steps** | From Σ E[Δ_k^q] < ∞, show estimate errors are eventually below Δ_k/m almost surely, then run the deterministic Clarke argument on unsuccessful iterations. | [S067 pp. 12–14] |
| **Spherical caps** | Lower-bound the probability that a uniform direction is κ-descent via the spherical cap (regularized incomplete Beta); use the same caps to show limit directions are dense with probability one. | [S019 pp. 25–26; S050 p. 9] |
| **Rival conditions imply yours** | Before calling a condition "weaker", prove each rival assumption implies it (conditional Chebyshev, event inclusion) or show the standard scheme is a degenerate case of yours. | [S067 p. 9, pp. 29–30; S102 p. 7] |
| **O(α_k) error budgets for stochastic-gradient templates** | Give every inexactness source (lower-level solve, bias, drift) a budget of order α_k and track one Lyapunov term per level. | [S017 pp. 13–14; S042 pp. 13–18; S091 pp. 14–16; S093 pp. 8–10; S111 pp. 15–16; S107 pp. 11–13] |
| **Mirror the gradient-method proof** | In convex and strongly convex classes, follow the gradient-method proof step for step and substitute the method's own decrease inequality. | [S046 pp. 3–4, 9, 13–14; S015 pp. 6–8; S017 pp. 13–16; S042 pp. 19–20; S107 pp. 8–10; S111 pp. 8–9] |
| **Implicit-function sensitivity** | Differentiate the solution map (of a lower level, a scalarized MOO problem, a trust-region subproblem) with the implicit-function theorem to get sensitivities and curvature. | [H004 pp. 4–5; S099 pp. 5–6; S062 pp. 3–4; S098 pp. 9–14; S042 p. 7; S070 pp. 8, 10; S096 pp. 11–12, 19–20] |
| **Geometry and poisedness** | Control sample geometry with Λ-poisedness; after an unsuccessful poll with step-tied radius, the last poll set is Λ-poised for free; bound poisedness by the cosine measure. | [S010 pp. 8–10; S020 p. 4; S008 pp. 10–11; S030 p. 10; S029 pp. 11–15] |
| **Extend the function, then contradict** | At a discontinuity, extend the function from one piece to a Lipschitz function with a designed property (strict decrease on a cone), apply the Lipschitz theory to the extension, and derive where poll points must go. | [S024 pp. 13–17] |
| **Case split by mode or iteration type** | Analyse feasibility/optimality modes, restoration branches or Full/Low iteration types separately and state extra hypotheses only in the branch that needs them. | [S049 pp. 4, 12; S073 pp. 4, 10–11; S032 pp. 7, 9–10; S006 pp. 15, 17; S007 pp. 21–22] |
| **Boundary-marking constructions** | Publish the conjecture with the inequality that fails, a saddle counterexample, a sharpness example with a threshold sweep, or the natural merit function shown to increase. | [S014 pp. 20–21; S074 p. 8; S108 pp. 77–84; S110 p. 5; S023 p. 8] |

## 2. Algorithm-design moves

| Technique | How to use it | Cards |
|---|---|---|
| **Name the proof-free slots** | Rewrite the base algorithm with its theory-free procedures as named slots ([search], [order], [mesh]); put each contribution in a slot and show the slot's requirements still hold. | [S008 pp. 3–4, 13; S059 pp. 4–7] |
| **Efficient component in a proof-free slot** | Put the heuristic (swarm, model minimizer, FD-BFGS step, user/physics move) in the search step, the poll order or a Full-Eval iteration; the poll carries convergence. | [S008 pp. 3–4; S005 pp. 8–10; S025 pp. 6, 9; S012 p. 8; S064 pp. 7–8; S071 pp. 3–4; S073 pp. 5, 10; S039 p. 4] |
| **Decouple the heuristic's step; reset or switch** | Keep the heuristic's own step length apart from the convergence-controlling one; contract the latter on failure, reset to the larger of the two on success (σ_{k+1} = max{σ_k, σ^ES_k}), or accept fast steps only while β ≥ γρ(α) and otherwise switch to direct search. | [S050 pp. 6, 11; S057 p. 4; S073 pp. 5–6; S088 p. 6; S104 pp. 4–5] |
| **Enumerate acceptance variants, keep the provable ones** | Propose several sufficient-decrease tests (mean/mean, max/max, max/mean), drop the one you cannot prove and say why, and let profiles rank the rest. | [S050 pp. 4–5, 13–14] |
| **Tie the model or sampling radius to the step size** | Set the sampling radius proportional to the last step (Δ_k = σ_k α_{k−1} max‖b‖) so geometry is scale-free and constants are maxima over finitely many bases. | [S008 p. 10; S012 p. 7; S064 p. 8; S089 p. 7] |
| **Reuse information already paid for** | Store evaluated points; build simplex gradients or MFN/regression models from them to order the poll and feed the search step at no extra evaluation. | [S008 pp. 7–9; S012 p. 7; S059 pp. 3–4; S064 p. 22; S074 pp. 5–6, 10–12; S089 pp. 12–13] |
| **Handle constraints by evaluation status** | Relaxable constraints go into a merit function with restoration; unrelaxable ones get an extreme barrier; linear ones get tangent-cone generators. | [S049 pp. 4–6, 13; S018 pp. 5, 11; S057 pp. 3, 9–10; S045 p. 7; S088 p. 5] |
| **Lift a single-point method to a list** | Make the iterate a list of nondominated points, define success as "the list changed", and state which list elements must be kept for the proof. | [S003 pp. 4–7; S016 p. 13; S017 p. 18; S065 p. 9] |
| **Split one step into parts with their own measures** | Decompose a step into normal/tangential, first/second-order or feasibility/optimality parts, each with its own step size or acceptance measure. | [S007 pp. 6–7; S011 pp. 10–20; S040 pp. 95, 99; S060 pp. 3, 5–6] |
| **Tie inexactness to progress with implementable tests** | Require accuracy proportional to the step size, radius or predicted decrease, checked with quantities available at the iteration (no Lipschitz constants). | [S040 p. 136; S013 pp. 2, 10, 16; S047 pp. 8, 14; S085 pp. 4–5; S097 p. 8; S073 pp. 12–13; S088 pp. 13–14; S042 pp. 13, 20–21] |
| **Accuracy on the acceptance quantity** | Put the probabilistic or deterministic accuracy requirement on the estimated decrease the acceptance test uses, scaled with the sufficient-decrease power q. | [S067 pp. 3, 5–8; S102 pp. 5–7; S110 pp. 14–15; S013 pp. 9–10] |
| **Decide, don't estimate** | Pose a noisy accept/reject decision as a sequential test on the sign of a mean, with asymmetric error (P(accept \| unacceptable) ≤ C/µ), so easy decisions stop early. | [S102 pp. 5–7, 10] |
| **Turn a proof threshold into an implementation rule** | Convert the theory's threshold into a printed rule: number of random directions m > log₂[1 − ln θ/ln γ], radius factors, test boundaries ±σ²/(2eC), schedule exponents. | [S019 p. 20; S045 p. 16; S027 p. 8; S102 p. 18; S107 p. 24; S108 pp. 84–85] |
| **Encode weights as effort or schedules** | In gradient-based multiobjective learning, alternate objectives with step counts or frequencies and state the implied weighted function; sweep them to trace a front. | [S065 pp. 4, 8; S093 pp. 3, 15–17; S111 p. 4] |
| **Reformulate so an existing solver applies** | Recast the problem (bilevel as multicriteria, cardinality as biobjective, a knee as a low-dimensional outer problem) so a known solver, possibly a DFO one, runs unchanged. | [S022 p. 12; S036 p. 6; S061 p. 14; S080 p. 4; S101 p. 9; S096 pp. 8–9] |

## 3. Experiment protocols

| Technique | How to use it | Cards |
|---|---|---|
| **Evaluations as the unit** | Count cost in function (or sample) evaluations, with budgets in multiples of n+1 or n; enforce the budget in wrappers and report overshoots. | [S005 p. 16; S012 p. 10; S049 pp. 14–15; S050 pp. 12–13; S073 p. 17; S088 pp. 18–19; S079 p. 21] |
| **Profiles fitted to the class** | Stochastic solvers: best/average/worst over runs; shifted ratios near zero; MOO: purity only pairwise, spread kept out of data profiles (not monotone in the budget); noisy f: profiles on the true f, each repeated run counted as a problem. | [S005 p. 17; S018 pp. 14–15, 20; S003 pp. 17–20; S016 p. 6; S065 p. 11; S067 p. 19; S102 p. 17] |
| **Two-regime benchmark for a globalized heuristic** | Run data profiles at small budgets (50n) and performance profiles against long-run f*, then a separate multimodal suite with medians over random starts to check the heuristic's original strength survived. | [S050 pp. 12–18; S057 pp. 11–18] |
| **Ablate the hybrid against each component** | Include each part of the hybrid (swarm alone, poll alone; BFGS alone, direct search alone) as its own solver with identical parameters. | [S005 pp. 26–27; S073 pp. 14, 17–22; S088 p. 17; S064 pp. 9–13; S071 pp. 15–16; S102 pp. 17–18; S079 p. 21] |
| **Mechanism-isolating control** | Add one variant that removes the mechanism you credit (random vs orthogonal poll, decoupled vs coupled step, test swapped with everything else fixed) and a diagnostic of the mechanism itself (how often the surrogate direction is a descent direction). | [S074 pp. 20–21; S060 pp. 13, 15; S045 p. 17; S058 p. 22; S110 pp. 18–19; S008 p. 18; S091 pp. 8–9] |
| **Fairness to baselines** | Tune the baseline first, give rivals the oracle constants their theory needs, withhold the same starting information from all, use one step-size grid per method, rerun a motivating experiment that favoured you, write the stopping-tolerance rule down. | [S008 p. 14; S046 pp. 21–22; S018 p. 13; S042 p. 26; S019 p. 20; S012 pp. 15–16; S029 p. 25; S045 p. 22] |
| **Known-answer validation** | Generate instances with planted solutions and controlled difficulty, certified against competitors' assumptions; in applications climb calibrated case → synthetic with known answer → real data. | Generators [S053 pp. 1–2, 4–9, 14; S026 pp. 1, 9–10, 15–16; D001 pp. 1–4]; planted truth [S028 pp. 14–15; S075 pp. 4–8; S087 pp. 8–17; S082 pp. 4–5]; closed-form lower level [S042 p. 26] |
| **Assumption-boundary suite** | Build one test function per hypothesis, each violating exactly one; rerun at a tighter tolerance to separate slow asymptotics from a violated assumption. | [S024 pp. 17–23; S108 pp. 80–84; S083 p. 7] |
| **Robustness over definitions and parameters** | Rerun under other budgets, tolerances, variances, definitions and parameter grids, and report the outcome in one sentence. | [S092 pp. 7–9; S096 pp. 16–19; S102 p. 18; S073 p. 22; S016 p. 5] |
| **Honest aggregate tables** | Report average % change in evaluations vs the baseline, its 75th percentile, how often the add-on was active, and cumulative accuracy thresholds; move the full grid to a companion report. | [S008 pp. 14–16] |
| **Public collection and code** | Recode the test set (AMPL, CUTEst subsets, Moré–Wild) and publish it with the solver or repository. | [S005 p. 14; S003 p. 15; S059 pp. 1–2; S016 p. 5; S042 p. 22; S088 p. 14; S091 p. 7; S079 p. 3] |

## 4. Writing moves

| Technique | How to use it | Cards |
|---|---|---|
| **Old theories as special cases, in the abstract** | Say in the abstract which known results the new one contains. | [S011 p. 2; S013 pp. 1–2; S040 pp. 19–20; S111 p. 5; S003 p. 14] |
| **Algorithm box that marks the diff** | Print the base method and the modified one in the same format, with changes in italics or brackets, so "minimal change" can be checked line by line. | [S008 p. 7; S018 p. 6; S059 pp. 4–5; S050 pp. 3–6; S107 p. 7] |
| **Phenomenon or worked example first** | Open with the observed phenomenon (the L-shaped f-vs-evaluations curve; a surprising random-direction result) or a three-iteration worked example before the theory. | [S008 p. 1; S019 pp. 2, 6–7; S003 pp. 7–9; S017 pp. 9–10; S110 pp. 4–6] |
| **Price or restriction in the abstract** | State what the generalization costs (one order worse, biased direction, restricted to scalarized methods) in the abstract. | [S015 p. 1; S017 p. 1; S096 p. 1; S089 p. 1; S107 p. 1; S073 p. 1] |
| **Separate "for the theory" from "in practice"** | Label every place the code departs from the analysed algorithm, with the reason, in a footnote or numbered remark next to the experiments. | [S005 p. 15; S018 pp. 7, 10–11; S050 p. 11; S012 p. 8; S003 p. 20; S067 pp. 20–21; S110 pp. 10, 20] |
| **Close with a mechanistic reason or specific open problems** | End with why the proof stops (poll points approach a boundary slower than the iterates) or with numbered open problems and their status. | [S024 p. 23; S041 p. 8; S083 p. 8; S091 p. 6; S110 pp. 14, 22] |
| **Credit priority and rivals precisely** | Credit concurrent or earlier results in the introduction with their exact restriction, and scale the novelty claim accordingly. | [S015 p. 2; S038 p. 12; S041 p. 2; S110 p. 3] |
| **Target property as a numbered definition in the other community's terms** | When bringing a guarantee to a heuristic community, define the property you add in that community's language and cite what it already knows. | [S050 p. 2] |
| **Survey by problem feature or component** | Organize a survey as a routing table from problem features (smooth, nonsmooth, noisy, constrained) to method classes and released software. | [S038 pp. 2, 4–13; S055 pp. 2–3; S056 pp. 7–9] |
| **Tables of constants and notation** | Collect constants and their dependencies in a table (or a list right after the corollary) so readers can check every O(·). | [S006 p. 4; S014 p. 3; S023 pp. 7–8] |
| **Paper architecture** | Pair a method paper with a software paper, or a theory paper with an application paper; publish an interface, a generator or a dataset as its own citable paper. | [S026 p. 1; D001 p. 1; S048 pp. 1–4; S017 p. 19 → S016 p. 4; S107 → S101 pp. 15, 25–26; S086 p. 1] |
