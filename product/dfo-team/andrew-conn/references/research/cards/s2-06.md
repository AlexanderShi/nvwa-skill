### S120 · A numerical comparison between the LANCELOT and MINOS packages for large-scale nonlinear optimization: the complete results (Tech. Rep. 97/14, Department of Mathematics, FUNDP, Namur 1997, no DOI/arXiv)
**Role**: supplement · **Coauthors**: I. Bongartz, N. I. M. Gould, M. A. Saunders, Ph. L. Toint · **Position in trajectory**: LANCELOT/CUTE period, with Conn at IBM T.J. Watson (p. 1). This is the data companion of Report 97/13, which holds the comparison and its discussion (pp. 2, 51). Saunders (Stanford, p. 1) co-wrote MINOS, which S054 attributes to Murtagh and Saunders (S054 p. 29). **Read**: pp. 1–3 (cover, abstract, introduction, §2 definitions), p. 27 (§3 protocol) and p. 51 (references) in full. The 23 dimension tables (pp. 4–26) and the 23 result tables (pp. 28–50) were scanned and tallied by script, not read row by row.

- **D1 Problem & entry**: The entry is transparency, not a new question.
  - Report 97/13 compared the default versions of LANCELOT and MINOS on 913 CUTE problems and discussed statistical summaries (p. 2).
  - This report supplies the full per-problem data, "intended mostly for reference" (p. 2).
- **D2 Core idea & design**:
  - First table set: per-problem dimensions (n, m, free, fixed and bounded variables, linear and nonlinear objective groups, four constraint counts). The counts obey n = nfr + nfx + nb and m = nle + nne + nli + nni (p. 3).
  - The class labels (LP, QP, BC, LC, NC) are derived from these counts; for example, NC means nne > 0 or nni > 0 (pp. 3, 27).
  - The number of nonlinear objective groups (from LANCELOT's group-partially-separable format) serves as a measure of how nonlinear the objective is (p. 3).
  - Second table set: function evaluations and CPU time of each package on each problem (pp. 28–50).
- **D3 Assumptions & model**: none stated. Only default options of both packages were run (pp. 2, 27).
- **D4 Analysis**: none (data report).
- **D5 Experiments**:
  - Setup: 913 CUTE problems, both packages on default settings. CPU seconds were measured on a 333 MHz DEC Alphastation 500 under Digital Unix 4.0A with default f77 options (p. 27).
  - Failure codes: P (no further progress), T (12000-second CPU limit), E (arithmetic error), F (no feasible point) and W, "optimality was wrongly reported" (p. 27).
  - The report gives no summary statistics; they are in 97/13 (p. 2).
  - My own tally (not stated in the report) covers the 912 rows the script could parse. LANCELOT ended abnormally on 94 (48 T, 29 P, 14 F, 3 E) and MINOS on 105 (56 E, 22 W, 18 P, 9 T).
  - On the 744 rows where both packages succeeded, LANCELOT used fewer function evaluations on 609 and MINOS on 129. MINOS used less CPU time on 563 and LANCELOT on 156 (pp. 28–50). **Which package wins flips with the cost unit.**
- **D6 note**: the comparison is co-signed by an author of the rival package (Saunders, p. 1).
- **D8 Contribution & limits**:
  - Contribution: infrastructure and data. It is a complete, reusable per-problem record on a public test set (pp. 2–3).
  - Limits: default options only; no discussion in this report; CPU times are tied to one machine (p. 27). No future directions are given.

**Method links**:
- Method 2 ✅ (evidence): public collection (913 CUTE problems), reproducible problem descriptors, a failure taxonomy, and complete per-problem results published as a separate document (pp. 2–3, 27).
- Method 1 ✅ (evidence): companion-report structure. The discussion is in 97/13 and the data in 97/14 (p. 2).
- Method 2 ⚠ (variant), step 1: the report gives both function evaluations and CPU time rather than the single unit the user pays for. My tally shows the two units rank the packages in opposite directions (pp. 28–50).
- new-pattern candidate: **Rival-inclusive benchmarking**. The comparison with a rival package is co-authored by that package's author (Saunders, p. 1).
- new-pattern candidate: **Complete-results companion report**. Publish every per-problem number separately so that a short paper's summaries can be checked (p. 2).

**Transferable techniques**:
- Publish every per-problem number in a companion technical report: both cost units, plus a coded failure reason. Cite the report from the main paper (pp. 2, 27).
- Use a failure taxonomy that separates no further progress, time limit, arithmetic error, no feasible point and optimality wrongly reported (p. 27). The last code catches false successes that a pass/fail flag hides.
- Tabulate structural descriptors of each test problem together with consistency identities (n = nfr + nfx + nb, m = nle + nne + nli + nni), and derive class labels from the counts so that they are reproducible (p. 3).
- Report results in two cost units (evaluations and CPU). A tally of the S120 tables shows that the ranking can reverse between them (pp. 28–50).

**Quotes**:

### S039 · Noise considerations in circuit optimization (ICCAD 1998, DOI 10.1145/288548.288617)
**Role**: supplement · **Coauthors**: R. A. Haring, C. Visweswariah, all at IBM T.J. Watson (p. 1) · **Position in trajectory**: JiffyTune circuit-tuning line (Method 4). It cites the ICCAD 1996 and 1997 papers and the TCAD JiffyTune paper (then to appear) as refs [5], [6], [10], and the two-step paper S056 as "under review" (ref [16]) (p. 8). **Read**: full text (pp. 1–8).

- **D1 Problem & entry**: The entry is an industrial design trend.
  - Lower supply and threshold voltages, denser packing, faster edges and more dynamic logic make noise a design criterion alongside delay, power and area (p. 1).
  - Mathematically, noise checks are semi-infinite constraints over time, and the numbers of signals and time windows to check can be very large. The authors state that no practical solution existed in the literature (p. 1).
- **D2 Core idea**:
  - Reformulation: the semi-infinite constraint v(x,t) ≥ NMH for all t ∈ [t1,t2] becomes one equality, c(x) = ∫ max{NMH − v(x,t), 0} dt = 0. It holds exactly when the original constraint holds (problem (2), p. 2).
  - The integral is the area of the "noise bump". It is computed from the time-domain simulation the optimizer already runs (p. 3).
  - Gradient: the crossing times ts(x), te(x) move with x. Writing the integral with unit-step functions and differentiating produces boundary terms, and these vanish because the integrand is zero at the crossings. What is left is ∂c/∂x = ∫ from ts to te of −∂v/∂x dt (eqs. (4)–(8), p. 3).
  - Cost: instead of one gradient per measurement, the gradient of the optimizer's scalar merit function Φ = t0 + Σ λi ci is computed in a single adjoint analysis. All excitations are applied simultaneously, so the cost does not depend on the number of variables, signals or time windows (p. 4).
  - General form: a noise objective is handled through an auxiliary variable z (problems (10)–(12), p. 4), and minimax variants follow the same route (eqs. (20)–(23), p. 5). The device works for any differentiable merit function, including penalty and barrier functions (p. 5).
  - Kept: LANCELOT and the SPECS simulator with adjoint sensitivities inside JiffyTune (p. 6). Changed: how the semi-infinite constraints enter.
- **D3 Assumptions & model**:
  - The waveform is continuously differentiable in x and t (footnote 1, p. 2).
  - Simple bounds are kept satisfied, so z ≥ 0 (footnote 2, p. 4).
  - The simulator and the optimizer must "cooperate closely" (p. 4).
- **D4 Analysis (brief)**: There is no theorem. The devices are:
  - Equivalence of the integral equality with the semi-infinite constraint (p. 2).
  - Differentiation of an integral with x-dependent limits through unit steps and Dirac impulses, where the boundary terms cancel because the integrand vanishes at the crossings (eqs. (5)–(8), p. 3; conditions (16)–(19), p. 5).
  - An adjoint current source u(t − ts) − u(t − te) at the measurement node (p. 3).
  - Reader's note (not in the paper): at any feasible x the positive part is zero on the whole window, so ∇c(x) = 0 there, and the equality constraint is degenerate at feasible points. The paper only relates the constraint to penalty functions for semi-infinite programming ([7], p. 3).
- **D5 Experiments**:
  - A dynamic AND gate (Fig. 1) was tuned in 9 iterations, with waveform snapshots shown (p. 6).
  - A delay–noise tradeoff sweep varied the noise margin from 50 mV to 300 mV (Fig. 4, p. 7).
  - A scaling test used a 144-MOSFET branch-scan circuit with 36 delay measurements, 1–104 tunable transistors and 1–459 noise functions. The gradient overhead over the nominal simulation grew from 3% to 18% with the number of parameters and hardly at all with the number of noise functions (Fig. 5, p. 7).
  - There is no baseline method.
- **D8 Contribution & limits**:
  - Contribution: an algorithmic device built into a deployed tool. JiffyTune had tuned PowerPC and S/390 circuits with over 10,000 tunable transistors (p. 6).
  - Future work: static timing, wire spacing, package design and electromigration (p. 8); automating the specification of noise constraints (p. 8).
  - Limits: the stated limits are practical; there is no convergence discussion.

**Method links**:
- Method 5 ✅ (evidence): derivatives come from the simulator through adjoints, and the scalar structure of the merit function is exploited so that one adjoint gives all gradients (pp. 3–4). This is a direct case of Heuristic 1.
- Method 4 ✅ (evidence): the problem comes from industrial design trends (p. 1); the solution lives in the designers' tool, with a schematic GUI (p. 6); and the future work is about usability, namely automating the noise-constraint lists (p. 8).
- Method 6 ✅ (evidence): the semi-infinite reformulation is tied to the Conn–Gould exact penalty for semi-infinite programming ([7], p. 3), and LANCELOT's augmented Lagrangian is reused inside the circuit tool (p. 6).
- new-pattern candidate: **Differentiate the merit function, not the constraints**. When the optimizer only needs ∇Φ of a scalar merit function, one adjoint solve replaces one sensitivity computation per constraint (p. 4).

**Transferable techniques**:
- Replace a semi-infinite constraint g(x,t) ≥ 0 for all t by the equality ∫ max{−g(x,t), 0} dt = 0, computed from a simulation you already run. Its gradient is the integral of ∇g over the violation intervals, because the boundary terms vanish (pp. 2–3).
- If the optimizer's inner loop only uses the gradient of a Lagrangian or penalty merit function, weight the adjoint excitations by the current multipliers. One adjoint analysis then gives the whole gradient (p. 4).
- Scaling protocol for derivative computation: vary the number of parameters and the number of constraints independently, and plot the overhead as a percentage of the nominal simulation (Fig. 5, p. 7).

**Quotes**:
- "Thus a large number of noise considerations can be incorporated with a very small impact on run time." (p. 7)
- "The generation of the list of noise constraints for a large circuit can be a tedious job." (p. 8)

### S056 · Two-step algorithms for nonlinear optimization with structured applications (SIAM Journal on Optimization 1999, DOI 10.1137/s1052623498334396)
**Role**: supplement · **Coauthors**: L. N. Vicente (Coimbra; the work started while he visited IBM, p. 1), C. Visweswariah (IBM) · **Position in trajectory**: it links the LANCELOT code (SBMIN, p. 16) to the JiffyTune circuit tool (p. 17). It is the first Conn–Vicente paper in this batch, a decade before CSV 2009. **Read**:
- in full: abstract, §1, §2 (algorithms), §4 (Algorithm 4.1 and Corollary 4.1 with its proof), §6 including the tables, and §7;
- §3: Theorems 3.1–3.2 with their proofs and Remark 3.1; Theorems 3.3–3.5 as statements;
- §5 (pp. 12–15): the slack and minimax updates and the statement of Proposition 5.1; its proof (pp. 13–14) only in part.

- **D1 Problem & entry**:
  - Setting: when function and gradient evaluations are expensive, one wants as much improvement per iteration as possible (p. 1).
  - Entry: some variables (slacks, the minimax variable z) enter the objective in a known, cheap algebraic form. A cheap second step in those variables can therefore follow the classical step (p. 1).
  - Motivation: updating slack and minimax variables at every iteration of LANCELOT's trust-region algorithm (p. 3).
- **D2 Core idea**:
  - Greedy two-step trust region (Algorithm 2.2, p. 4): compute the TR step s_k, then any ŝ_k with f(y+s+ŝ) < f(y+s), and test acceptance on the sum.
  - New reductions (eqs. (3)–(4), p. 4):
    - ared = f(y) − f(y+s+ŝ);
    - pred = [m(y) − m(y+s)] + [f(y+s) − f(y+s+ŝ)], that is, the model decrease of the first step plus the *actual* decrease of the second.
    - The alternative pred = m(y) − m(y+s+ŝ) is rejected because ŝ is not computed from the model (p. 4).
  - Conservative variant (Algorithm 2.3, p. 5): take ŝ only after an accepted first step. The conservative line-search version is the known spacer step of Bertsekas and Luenberger (p. 2).
  - Slack application: for fixed x, LANCELOT's augmented Lagrangian is a quadratic in the slacks, so the optimal slack update is explicit, u_i = max{0, …} (eq. (27), p. 13), and needs no function or gradient evaluation (p. 13).
  - Minimax application (31): the joint update of the slacks and z solves a scalar piecewise-linear equation in O(m) operations (eqs. (34)–(36), p. 15).
  - Further candidates: variables that occur linearly, such as arrival times in static-timing circuit problems (p. 15).
- **D3 Assumptions & model**:
  - Unconstrained analysis (1) with f twice continuously differentiable (p. 2).
  - Bounded {H_k} (5) and a fraction of Cauchy decrease (6) (p. 5).
  - For the lim-type result: ∇f uniformly continuous, and either a decrease ≥ κ1‖ŝ‖ (12) or ‖ŝ‖ ≤ κ2Δ (13) (p. 7).
  - For second order: a fraction of optimal decrease (17), exact Hessians and a compact level set (p. 9).
  - The extension to simple bounds (LANCELOT's SBMIN) is called "entirely straightforward" but not proved (p. 13).
- **D4 Analysis (brief)**:
  - Theorem 3.1 (pp. 6–7): the second step only adds actual decrease, so pred still satisfies the Cauchy bound (8) (p. 6). Also, |ared − pred| is the Taylor error of the first step alone (11). Moré's classical argument therefore goes through and gives liminf ‖∇f‖ = 0 with no size restriction on ŝ. The authors remark that this may seem surprising (p. 7).
  - Remark 3.1: ρ̂ = (t + ρ)/(t + 1), where t is the second step's gain ratio. The combined test accepts every step the standard test accepts, and more when ρ < 1 (p. 7).
  - Theorem 3.2: lim ‖∇f‖ = 0 needs (12) or (13) (p. 7). The proof follows Moré's Theorem 4.14 (pp. 7–8).
  - Theorem 3.3 gives a second-order limit point (p. 9). Theorems 3.4–3.5 give eventual success and a trust radius bounded away from zero (pp. 9–10).
  - In the applications, the second step decreases f by ≥ κ5‖ŝ‖² (21), by convexity of the slack quadratic (Proposition 5.1, pp. 13–14). Algorithm 3.1 then scales ŝ so that (12) or (13) holds (p. 10).
  - The authors state that Theorem 3.2 with (21) in place of (12) is unlikely to hold (p. 11).
  - Two-step Newton (Algorithm 4.1): a second Newton step in a subset of variables keeps q-quadratic convergence (Corollary 4.1, pp. 11–12). The proof uses the perturbation lemma and Lipschitz continuity of ∇_u f.
- **D5 Experiments**:
  - Code: LANCELOT Release A modified inside SBMIN, in three versions (pp. 15–16).
  - Problems: 56 CUTE problems (26 non-minimax, 30 minimax), with the selection rule in a footnote (p. 16). Reported: INFORM flag, iterations, CPU time and objective value (p. 16).
  - Headline: about 15% fewer iterations on average, with HS109 and HAIFAM (much better) and POLAK6 (worse) excluded (p. 16).
  - Second tier: JiffyTune dynamic-simulation circuit problems with loose tolerances and noise safeguards (pp. 17–18; Table 6, p. 22), and static-timing minimax circuits of growing size (Table 7, p. 23).
  - Failure section §6.3: minimax problems on which two-step updating is much worse (pp. 19–24).
- **D8 Contribution & limits**:
  - Contribution: theory (two-step TR convergence and the two-step Newton rate), algorithm and software (the LANCELOT modification), and application (circuits).
  - Limits, stated concretely:
    - Two-step updating is unlikely to help asymptotically on small, cheap problems (p. 17).
    - On some minimax problems the second step pushes iterates towards points where the augmented-Lagrangian Hessian is ill-conditioned, which spoils the next first step (pp. 21–22). Two fixes, a tighter CG tolerance and a larger initial penalty parameter (Versions 4–5, Table 8), are tested (pp. 22–24). General strategies are left to future research (p. 23).
  - D6: spacer steps and the NPSOL/SNOPT slack updates are acknowledged as prior work (pp. 2, 13). Variable elimination (Golub–Pereyra) is named as the alternative approach (p. 2).

**Method links**:
- Method 5 ✅ (evidence): variables with a known functional form (slacks, the minimax variable z) are updated in closed form instead of being left to the generic TR step (pp. 13, 15).
- Method 1 ✅ (evidence): a class-level theorem (any decreasing second step), code (modified SBMIN) and numbers on CUTE and circuits, all in one paper (pp. 4–23).
- Method 2 ✅ (evidence): two tiers reported separately, CUTE analytic problems and industrial circuit problems, plus a size-scaling family (Table 7) (pp. 16–23).
- Method 4 ✅ (evidence): circuit evaluations that take over ten minutes each justify the extra machinery (p. 18).
- new-pattern candidate: **Dedicated failure-analysis section**. §6.3 isolates the problems where the method is much worse, explains the mechanism (Hessian ill-conditioning) and tests fixes (pp. 19–24).
- new-pattern candidate: **Credit cheap extra decrease in the acceptance ratio**. The actual decrease of any cheap post-step is added to the model's predicted decrease (pp. 4, 7).

**Transferable techniques**:
- To add a cheap bonus step to a trust-region method without breaking its theory, define pred as the model decrease of the TR step plus the actual decrease of the bonus step. liminf convergence follows unchanged; for lim convergence, bound the bonus step either by Δ or by its own decrease (pp. 4–7).
- Show that the modified acceptance ratio increases with the bonus gain, so every step the standard test accepts is still accepted (Remark 3.1, p. 7).
- In augmented-Lagrangian subproblems, update slack (and minimax) variables in closed form after every step (eqs. (27), (34)–(36), pp. 13–15).
- Report averages with the exclusions named in both directions (HS109 and HAIFAM better, POLAK6 worse), and then give the bad cases their own section (pp. 16, 19–24).

**Quotes**: none given. The text file replaces each lowercase letter c with a carriage-return character, so no sentence of this paper can be quoted both verbatim and legibly.

### S054 · A primal-dual algorithm for minimizing a non-convex function subject to bound and linear equality constraints (Nonlinear Optimization and Related Topics, Kluwer 2000, DOI 10.1007/978-1-4757-3226-9_2)
**Role**: supplement · **Coauthors**: N. I. M. Gould, Ph. L. Toint · **Position in trajectory**: the CGT trio's first primal-dual interior-point method, motivated by named drawbacks of LANCELOT (p. 2). It announces its trust-region successor (S026/S111) as current research by Conn, Gould, Orban and Toint (p. 9). The book is dated 1999 on its first page (p. 1). **Read**: abstract and §1 in full (pp. 1–14); Theorem 3 statement and proof outline (p. 15); Lemma 4 with proof (pp. 15–16); statements of Lemmas 5–7 (pp. 16, 18, 23); end of the main proof and the extension (p. 26); §3 numerical tests (pp. 27–29); §4 conclusion (p. 30). Not read: the proofs of Lemmas 5–7 (pp. 17–25) and the appendix (pp. 31–32).

- **D1 Problem & entry**:
  - Problem: minimize f(x) subject to Ax = b and x ≥ 0, with f non-convex (1.1) (p. 2).
  - Entry from the authors' own code (p. 2):
    - augmentation may not be the best way to treat linear constraints;
    - LANCELOT's SBMIN predicts the active bounds from the generalized Cauchy point, which is not effective on degenerate or nearly degenerate problems;
    - interior-point methods are usually held to be less sensitive to degeneracy.
    - General nonlinear constraints would still go through an augmented Lagrangian.
  - Gap: little work extends primal-dual methods to non-convex problems. Bonnans–Pola's analysis needs a strictly interior start and a convex model (p. 3).
- **D2 Core idea**:
  - Primal-dual Newton step on the perturbed KKT system with XZe = μe ((1.3)–(1.8), pp. 4–5).
  - All infeasibility in Ax = b is carried by one artificial scalar ξ with Ax − b = ξr0. A unit step then satisfies the linear constraints from that point on ((1.9)–(1.11), p. 5).
  - A second, "modified barrier" step comes from Newton's method on a shifted-penalty problem with the term ½ρ(ξ+1)² (pp. 5–6). It is used when the primal-dual step fails the descent test (Step 2, p. 11).
  - One merit function serves both steps: φ = f + ½ρ(ξ+1)² − μ⟨log x, e⟩ (p. 6). Descent is guaranteed when G is second-order sufficient in the null space of A and ρ is large enough (Lemmas 1–2, (1.25)–(1.26), pp. 7–9).
  - Non-convexity is handled by a modification ΔG_k that makes N^T G N, not G itself, positive definite (p. 9). Comment 9 argues this avoids slowing the asymptotic rate (p. 14).
  - The stated aim is one consistent method with a single merit function and a guaranteed descent direction (p. 3, paraphrase).
- **D3 Assumptions & model**:
  - AS1: f twice continuously differentiable. AS2: the iterates stay in a convex bounded subset D of the positive orthant. AS3: A has full rank. AS4: a strictly interior point satisfying Ax = b exists (pp. 3–4).
  - AS2 is an assumption on the algorithm's iterates; it is justified as automatic when the feasible domain is bounded (p. 4).
  - No feasible starting point is required (pp. 2–3).
- **D4 Analysis (brief)**:
  - Theorem 3: the set K of iterations where μ is reduced is infinite. Along K, complementarity, dual infeasibility and primal infeasibility all tend to zero (p. 15).
  - The proof is by contradiction with two cases, ρ bounded or ρ → ∞ (p. 15).
  - Key devices:
    - the monotone merit function bounds the artificial variable ξ (Lemma 4, (2.9)–(2.12), pp. 15–16);
    - for fixed μ and ρ, the steps tend to zero and XZe → μe (Lemma 6, p. 18);
    - increases of ρ eventually force primal feasibility (Lemma 7, p. 23).
  - The result is first-order only, on a subsequence.
  - Choosing z = μX⁻¹e turns the method into a pure primal one, which the authors flag as useful for exploiting negative curvature (p. 26).
- **D5 Experiments**:
  - Code: a prototype Fortran 90 code for QPs. Linear systems are solved with MA27 using a 10⁻⁶ pivot threshold and iterative refinement. G is replaced by G + ‖G‖I when it is not second-order sufficient (p. 27).
  - Problems: the larger CUTE QPs, not preprocessed (p. 27).
  - Reported: counts of modified-barrier steps and of Hessian modifications per problem (p. 29).
  - Baseline: the HSL active-set code VE09. Its iterations are much cheaper (a factorization update versus a refactorization). MINOS results were "quantitatively similar" to VE09 and are not reported (p. 29).
  - Outcome: good on convex problems except YAO. Disappointing on non-convex ones, because the naive modification removes negative eigenvalues one at a time (p. 29).
- **D8 Contribution & limits**:
  - Contribution: a theoretical framework with first-order global convergence, plus a crude prototype (pp. 3, 30).
  - Concrete limits: negative-curvature handling is too naive (pp. 29–30); the KKT matrix (4.1) is ill-conditioned, unlike its LP analogue (4.2); the normal equations are inappropriate here (p. 30).
  - Future work: a trust-region variant (p. 9); explaining why primal-dual should beat primal globally on non-convex problems; why the central path matters; predictor-corrector steps (p. 30).

**Method links**:
- Method 1 ✅ (evidence): theory, a prototype and CUTE numbers together, with columns (MB steps, Hessian modifications) that expose the weak spot (pp. 28–29). Across the pair, the failure drives the next design: the trust-region successor does as well on non-convex as on convex problems, in contrast with this method (S026 p. 33). This is Method 1 step 5 at work.
- Method 6 ✅ (evidence): LP primal-dual interior-point ideas are carried into non-convex NLP (p. 2), while LANCELOT's augmented Lagrangian is kept for nonlinear constraints (p. 2).
- Method 5 ✅ (evidence): linear constraints and bounds are handled explicitly rather than by augmentation (p. 2).
- new-pattern candidate: **Self-audit of one's own solver starts a research line**. Named drawbacks of LANCELOT (augmentation for linear constraints; Cauchy-point active-set prediction under degeneracy) motivate a new method (p. 2). S089 (batch s01) is another instance.
- new-pattern candidate: **Prototype-subclass testing**. A general NLP method is tested first on non-convex QPs, where a large test set and baseline numbers already exist (p. 27; also S026 p. 30).

**Transferable techniques**:
- Carry all linear-constraint infeasibility in one scalar ξ with Ax − b = ξr0. The Newton step in ξ is −ξ, so the infeasibility falls linearly with the step length, and a unit step removes it for good (p. 5).
- When a primal-dual direction may be uphill for the merit function, compute from the same factorization a second direction that is guaranteed to descend, and switch between them by a slope test (pp. 6–11; comment 8, p. 14).
- Modify only the reduced Hessian N^T G N, not G. Near a minimizer where the reduced matrix is positive definite, no modification is then needed (p. 9; comment 9, p. 14).
- Report per-problem counts of safeguard activations (modified steps, Hessian modifications) next to iterations and time, so readers can see where the safeguards do the work (p. 29).

**Quotes**:
- "In the non-convex case, the merit function is an essential ingredient of any successful algorithm and the choice of merit function was a considerable concern in the present paper." (p. 3)
- "On the other hand, its performance on the non-convex (NC) ones is somewhat disappointing." (p. 29)

### S026 · A primal-dual trust-region algorithm for non-convex nonlinear programming (Mathematical Programming 2000, DOI 10.1007/s101070050112)
**Role**: supplement · **Coauthors**: N. I. M. Gould, D. Orban, Ph. L. Toint · **Position in trajectory**: the trust-region successor of S054 (pp. 1–2, 33).
- Venue: Math. Program. Ser. B 87:215–249, dedicated to Bill Davidon's seventieth birthday; received July 1999, accepted February 2000 (p. 1).
- DOI: the file header prints DOI 10.1007/s101070000144 (p. 1), which differs from the DOI in the batch list.
- Versions and software: the report version is S111. The algorithm ships as the HSL package VE12 (p. 30).

**Read**:
- in full: abstract and §1–§2 (pp. 1–5), §3 (pp. 5–12), §5 and §6 (pp. 30–35);
- §4: the assumptions (§4.1); statements of Lemmas 1, 2 and 4 and Theorems 1–6; the proof of Lemma 1 and the first part of the proof of Theorem 5 (pp. 12–27).
- Not read: most proofs in §4.2–§4.4 (pp. 14–30).

- **D1 Problem & entry**:
  - Problem: minimize f(x) subject to Ax = b and c(x) ≥ 0, with f non-convex. General nonlinear equalities are excluded; they would probably be best handled by augmented-Lagrangian terms (p. 1).
  - The entry is the authors' previous paper, S054, in three changes (p. 2):
    1. A strictly feasible start (AS.1) removes most complications, which came from balancing feasibility against objective improvement; a phase-1 primal-dual method usually finds such a point quickly.
    2. Trust regions replace line searches, for second-order convergence guarantees, which the authors find especially attractive for non-convex problems.
    3. The inner and outer iterations are separated more clearly.
- **D2 Core idea**:
  - Outer loop: approximate sequential minimization of the log barrier φ(x, μ_k) = f − μ_k⟨e, log c(x)⟩ subject to Ax = b ((8)–(9), p. 5). Its stopping tests (23)–(27) include a second-order test (27) (p. 10).
  - Inner loop: a Newton-like trust-region method in the null space of A. The model replaces the primal barrier Hessian term μJᵀC⁻²J by the primal-dual term B = JᵀC⁻¹ZJ ((11)–(13), p. 6), justified by the Newton system of the perturbed KKT conditions ((14)–(17), p. 7).
  - Boundary handling: if the trial point fails the interiority test (22), c(x+s) ≥ ς c(x), the iteration is declared unsuccessful and the radius is cut, without evaluating the possibly undefined barrier (pp. 8–9).
  - Step quality: the model decrease must reach the larger of a Cauchy-type decrease and a negative-curvature decrease ((19)–(20), p. 8). GLTR can compute such a step (p. 9).
  - Trust-region norm: scaled by M = W + B so that the region reflects the problem's geometry ((21), p. 9). Convergence still holds although M blows up near the boundary (p. 12).
  - Dual update: the Newton value (75) is projected componentwise onto a safeguard interval ((76)–(78), p. 24).
  - What changed from S054: a line search with Hessian modification became a trust region, and the infeasible start through an artificial variable became a strictly feasible start (pp. 2, 8).
- **D3 Assumptions & model**:
  - AS.1: a strictly feasible x0 (p. 2).
  - AS.2: f and c twice continuously differentiable.
  - AS.3: A has full rank; the authors add that they "do not pretend" preprocessing to ensure this is easy (p. 3).
  - AS.4: the barrier is bounded below. It "might at first seem strong" but only rules out functions growing more slowly than the logarithm (pp. 3–4).
  - AS.5: bounded derivatives on a region containing the iterates. AS.6: dual bounds for each outer iteration. AS.7: bounded Hessian approximations. AS.8: uniform second-order sufficiency of the scaling matrices (p. 12).
  - AS.9–AS.10: asymptotic Hessian accuracy and dual centrality, needed for the second-order results (p. 21). Theorem 5 shows the safeguarded dual update satisfies AS.10 when the steps go to zero (p. 25).
- **D4 Analysis (brief)**:
  - Lemma 1: within one inner minimization, the iterates stay a fixed distance from the boundary ∂P, by a level-set argument on the barrier (p. 13). This lets the standard arguments with trust radii tending to zero run inside P (p. 13).
  - Lemma 2: within one inner minimization, all the scaled norms are uniformly equivalent (p. 14).
  - Chain of results: model error O(Δ²) for small Δ (Theorem 1, p. 16); radius bounded below while the gradient is bounded away from zero (Lemma 4, p. 17); all inner limit points first-order critical (Theorem 2, p. 19); asymptotic convexity of the model (Theorem 3, p. 22); finite termination of the inner iteration (Theorem 4, p. 24).
  - Theorem 6 (outer loop): first-order criticality, zero duals on inactive constraints and weak second-order conditions along every "consistently active" subsequence (pp. 26–27). The proof sorts the constraints into "eager" and "reluctant" ones by the ratio z_i/c_i (p. 27).
- **D5 Experiments**:
  - Scope: only non-convex QPs, a deliberate choice because test sets and earlier results exist for them (p. 30).
  - Code: VE12 (HSL), using GLTR (VF05) with a constraint preconditioner, switched automatically between diagonal and full factorizations according to CPU time per iteration (pp. 30–31). The initial point is the analytic centre computed by VE13 (p. 31).
  - Parameters: μ updated as min(0.1μ, μ^1.5), forcing functions μ^1.01, η1 = 0.01, η2 = 0.9 (p. 32).
  - Problems and baseline: the larger CUTE QPs, not preprocessed. The baseline is the HSL active-set code VE09; its iteration counts are "not directly comparable" and are shown for information only. Runs over 1800 s count as failures (p. 32).
  - Outcome: the new code wins on most small problems and is as successful on non-convex as on convex ones. Losses are named (PRIMAL*, DUAL*, QP*), and rank-deficient A defeats it (p. 33). Medium and large instances go up to 100001 variables, where VE09 exceeds 1800 s (p. 34).
- **D8 Contribution & limits**:
  - Contribution: theory (second-order global convergence even with unbounded scaling matrices), an algorithm and HSL software (pp. 30, 34).
  - Limits: tested on QPs only (p. 30); cannot cope with rank-deficient A (p. 33); memory limits on factorizing the preconditioner at about 10⁵ variables (p. 34).
  - Future work: more general models that agree to first order and have bounded second derivatives; general nonlinear equality constraints (p. 35).

**Method links**:
- Method 1 ✅ (evidence): the analysed algorithm is shipped as HSL VE12, "exactly the algorithm we analysed" (p. 30), and it is tested. Within the S054 → S026 pair, the numerical weakness of the first method (non-convex QPs) is the stated reason the second does better (p. 33; S054 p. 29).
- Method 6 ✅ (evidence): LP-style primal-dual interior-point ideas are combined with the trio's own trust-region machinery (pp. 2, 6–9).
- Method 2 ✅ (evidence): CUTE QPs; a rival from the other school (the active-set code VE09); an explicit warning that iteration counts are not comparable across the two (p. 32); named losses (p. 33).
- Method 3 ⚠ (variant): a model-geometry device outside DFO. The trust-region norm is built from the model Hessian to reflect the geometry of the problem (p. 9), and the theory tolerates unbounded scalings (p. 12). The instinct is the same (make geometry an explicit object of the method); the setting differs.
- new-pattern candidate: **Prototype-subclass testing** (p. 30; also S054 p. 27).
- new-pattern candidate: **Evaluation-free rejection**. A trial step is rejected by a cheap feasibility test before any evaluation of an undefined or expensive function (p. 8).

**Transferable techniques**:
- In an interior method, reject a trial point by the cheap test c(x + s) ≥ ς c(x) and shrink the radius, instead of evaluating a barrier that may be undefined (pp. 8–9).
- Require the step to achieve the larger of a Cauchy-type decrease and a negative-curvature decrease (19). One condition then serves both the first- and the second-order convergence proofs (pp. 8–9).
- Safeguard dual updates by projecting componentwise onto an interval built from the current iterate and μ ((76)–(78)), and prove that the projection keeps the asymptotic centrality the theory needs (pp. 24–25).
- For outer-loop convergence with inequality constraints, split the iterates into finitely many "consistently active" subsequences and prove the result on each one (p. 26).
- When comparing with an active-set code, show iterations for information only, compare CPU time, and count runs over a hard time limit as failures (p. 32).

**Quotes**:
- "This was quite deliberate since we have a large number of test examples in this case, and since we already have numerical results for these examples using other QP algorithms." (p. 30)
- "We believe that this is likely because negative curvature is better handled in the trust-region subproblem than through the ad-hoc matrix modification strategy which lays at the heart of our previous linesearch algorithm." (p. 33)

### S124 · Error estimates and poisedness in multivariate polynomial interpolation (Pré-Publicações do Departamento de Matemática, Universidade de Coimbra, Preprint 03-09, 2003, no DOI/arXiv)
**Role**: supplement · **Coauthors**: K. Scheinberg (IBM), L. N. Vicente (Coimbra; written while he visited IBM, p. 1) · **Position in trajectory**: the start of the CSV geometry programme that SKILL.md Method 3 lists (CSV 2008 *Math. Programming*, CSV 2008 *IMA JNA*, CSV 2009 *SIOPT*). The preprint's content (Λ-poisedness, error bounds and a Gaussian-elimination algorithm for the sample set) matches the topic of CSV 2008 *Math. Programming*, but I did not compare the texts. It builds on and improves the CST 1997 analysis (refs [3], [4]; pp. 2, 26–27).

**Read**:
- in full: abstract and §1 (pp. 1–5), §2 (pp. 5–11), §5 and §6 (pp. 23–31), §7 (pp. 31–32);
- partly: §3 definitions, statements of Lemmas 3.2–3.3 and Theorem 3.4 (pp. 12–19); the opening of §4 and the statement of Theorem 4.3 (pp. 21–23).
- Not read: the proofs in §3.2 (pp. 14–21), except the start of Lemma 3.2's proof.
- Text quality: the extraction loses many sub- and superscripts, and some constants, in Lemma 3.3 and Theorem 3.4 for example, are unreadable.

- **D1 Problem & entry**:
  - Need: DFO trust-region methods use interpolation models, which must have Taylor-like accuracy if the standard convergence theory is to apply (pp. 1–2).
  - Existing conditions (Powell, Sauer–Xu, Waldron) are tied to particular polynomial bases (Lagrange, Newton), and their error bounds are hard to understand intuitively (p. 2, paraphrase).
    - Waldron's paper is hard to follow for optimization readers (p. 2).
    - Powell's bound covers only function values, not derivatives (p. 2).
  - The condition number of the interpolation matrix depends on the basis and "can also be misleading" (p. 6).
  - Entry: a geometric, basis-independent well-poisedness condition that yields bounds on all derivatives directly (p. 2).
- **D2 Core idea**:
  - Λ-poisedness: take a set Y ⊂ B(Δ) that contains y0 = 0. Y is Λ-poised if, for every x ∈ B(Δ), φ(x) − φ(0) is a combination Σλ_i(φ(y_i) − φ(0)) with ‖λ‖ ≤ Λ (Definitions 2.1, 3.1, 4.1; pp. 6–7, 12, 22). By Lemma 1.1 the condition does not depend on the basis (p. 4).
  - Geometric reading in the linear case: the points cannot lie close to a lower-dimensional subspace; they form a "fat" simplex (p. 7).
  - Equivalences:
    - linear case: ΛL-poised in B(1) if and only if ‖L⁻¹‖ ≤ Λ (Lemma 2.2, p. 9); in B(Δ), ‖L⁻¹‖ ≤ Λ/Δ (Lemma 2.3, p. 10);
    - quadratic case: one direction holds up to a constant θQ (Lemma 3.2, p. 15);
    - Lagrange polynomials: equivalent to bounded Lagrange polynomials, up to a factor (p−1)^(1/2) (Proposition 5.2, pp. 24–25).
  - Algorithm 6.1 builds or repairs Y by Gaussian elimination, row by row. If no available point gives a pivot ≥ ξ, a new point is generated by maximizing the pivot polynomial over B(1) (pp. 27–28).
  - Proposition 6.1 bounds the pivots and hence gives an estimate of Λ (pp. 28–29). Maximizing each pivot polynomial reduces to a trivial enumeration because a value of 1/2 is guaranteed (p. 29).
  - Optimal linear geometries (pp. 29–31):
    - y_i = e_i gives ΛL = 1 for the L_{n×n} measure;
    - a simplex with uniform angles is optimal for the all-pairs measure, and it corresponds to the uniform minimal positive basis of pattern search (p. 31).
- **D3 Assumptions & model**:
  - Y lies in a closed ball centred at the origin; this is without loss of generality by a shift (p. 3).
  - y0 = 0: this is not strictly without loss of generality, since constants change by factors 2, 4 or 8, but it always holds in trust-region use, where the centre is the best point so far (pp. 3–4).
  - Smoothness: ∇f Lipschitz with constant γL in the linear case (p. 5), ∇²f Lipschitz with γQ in the quadratic case (p. 19), third derivatives Lipschitz in the cubic case (p. 23).
  - The number of points p equals the dimension of the polynomial space, i.e. fully determined interpolation (p. 3).
- **D4 Analysis (brief)**:
  - One device for all derivative errors (eqs. (8)–(10), p. 8):
    1. Subtract the model-error equation from the interpolation conditions.
    2. Expand f by Taylor's formula around the evaluation point x.
    3. Subtract the first equation from the others. The function error e_f cancels, leaving a linear system L e_g = O(Δ²) whose matrix does not depend on x.
  - Linear case: each right-hand-side entry is bounded by (5/2)γLΔ² (p. 9) and ‖L⁻¹‖ ≤ Λ/Δ. This gives ‖e_g‖ of order γL ΛL Δ times a dimension factor (the exponent is partly lost in the extraction). The O(Δ²) function error then follows a posteriori from (8) (Theorem 2.4, p. 10).
  - Quadratic case: Hessian error O(Δ), gradient error O(Δ²), function error O(Δ³) (Theorem 3.4, p. 19).
  - §5.3 explains why deriving derivative errors from a function-error bound fails in the quadratic case without extra assumptions. CST 1997 assumed bounded Hessians and so obtained only ‖e_g‖ = O(Δ), which the authors call "clearly inferior" and sufficient only for first-order convergence (pp. 26–27).
- **D5 Experiments**: none.
- **D8 Contribution & limits**:
  - Contribution: theory plus an algorithm for the model-geometry layer of DFO (pp. 31–32).
  - Limits stated:
    - the bound on e_f does not vanish at the interpolation points (p. 11);
    - an alternative all-pairs system may give smaller constants, and it is unclear which bound is better (p. 11);
    - the Newton-polynomial analysis is omitted (p. 26);
    - the norms ‖L⁻¹‖ and ‖U⁻¹‖ depend on the growth factor and are "expected to be of reasonable size" (p. 29).
  - Scope: only fully determined interpolation is treated (p. 3). The preprint contains no convergence theorem for an optimization algorithm; it says the analysis of CST 1997 "can now be simplified" (p. 26).

**Method links**:
- Method 3 ✅ (core evidence): model quality becomes an explicit, basis-independent constant Λ that appears in every error bound, and a repair algorithm is given (pp. 2, 6–10, 27–29, 31–32).
  - Steps 1–3 of Method 3 are all present.
  - Step 4 (a convergence proof that uses only the certified property) appears only as a promised simplification of the CST 1997 analysis (p. 26).
  - Step 5 (measure how often repair fires) is absent.
- Method 6 ✅ (evidence): the paper links interpolation geometry to pattern search. Shifting and scaling a good set chosen a priori is compared to the finite sets of positive bases used in pattern search (p. 27), and the optimal uniform simplex corresponds to the uniform minimal positive basis (p. 31).
- Method 1 ⚠ (variant): theory and an algorithm, but no code and no numbers.
- new-pattern candidate: **Geometric definition first, then prove equivalence to the algebraic one**. Well-poisedness is defined geometrically and then shown equivalent, up to constants, to ‖L⁻¹‖ and to Lagrange-polynomial bounds (Lemma 2.2, p. 9; Proposition 5.2, pp. 24–25).
- new-pattern candidate: **Explicitly improve one's own earlier analysis**. The paper states that its bound improves on the O(Δ) gradient bound of CST 1997 (pp. 26–27); compare the self-audit pattern in S054 and S089.

**Transferable techniques**:
- To bound all derivative errors of an interpolation model at once: write the model-error equations at the sample points, expand by Taylor's formula around the evaluation point, subtract one equation from the others so that the function error cancels, and invert the x-independent matrix that remains. The function-value error then follows from any single equation (pp. 8–10, 13–19).
- Prove the bound on the unit ball, then recover the dependence on Δ by a diagonal rescaling of the matrix (Lemma 2.3, p. 10; proof of Theorem 3.4, p. 19).
- Build or repair a sample set by Gaussian elimination with a pivot threshold. When no candidate point gives a large enough pivot, generate a new point by maximizing the pivot polynomial over the ball; a lower-bound lemma guarantees that the maximum exceeds the threshold (Algorithm 6.1, Lemma 3.3; pp. 17, 28–29).
- Before using a condition number as a quality measure, check whether it depends on the chosen basis. If it does, define a basis-invariant measure instead (p. 6).

**Quotes**:
- "To ensure the quality of the model one has to guarantee the well-poisedness of the interpolation set before seeking further accuracy by shrinking the size of the trust region (see, e.g., [3], [4])." (p. 2)
- "In practical situations only the geometry of the interpolation set is controllable." (p. 32)
