# Paper cards · batch s2-02 (supplement)

**Batch intent**: These are eight 2009–2014 papers from Scheinberg's Columbia/Lehigh years in structured convex and sparse optimization: row-by-row (RBR) methods for semidefinite programs (SDPs), SINCO, block coordinate descent for the Group Lasso, FISTA/FALM with full backtracking and LHAC. One paper is a derivative-free optimization (DFO) application (DFO-VASP). The questions are:
- How does Method 6 (exploit structure) look before the stochastic period?
- Does the Method 2 move (keep the classical method, repair the one thing that breaks) already appear in deterministic first-order work?
- Are there early, deterministic forms of Method 3 (complexity through the step-parameter trajectory) and Method 1 (accuracy tied to progress)?

**Focus dimensions**: D1, D2, D3, D4 (brief), D5 (one line), D8. This is the supplement short card. D6 and D7 appear only in the digest, one line each.
**Material roles**: all eight papers are supplement: S048, S049, S123, S067, S035, S085, S084, S028. S067 is unreadable, because its text file is a byte-identical copy of S028's (see the S067 card).

Reading note: page references use the `[[page N]]` markers of each extracted text file. Figures survive only as axis labels and captions (S049, S123, S028, S035, S084), and S085's Figure 4 has no caption in the file. Several files contain U+FFFE soft-hyphen artefacts inside words. ### S048 · Row by row methods for semidefinite programming (Industrial Engineering 2009, no DOI/arXiv)
**Role**: supplement · **Coauthors**: Z. Wen, D. Goldfarb, S. Ma (Columbia IEOR, p. 1) · **Position in trajectory**: Columbia-era structured convex optimization, dated April 28, 2009 (p. 1). The file is the technical report that S049 cites as submitted (S049 p. 21) and that the handbook chapter S035 extends (S035 ref. [67], p. 32). S049 calls SINCO a simplified RBR method (S049 p. 5). Scheinberg's affiliation is not printed in the text file. **Read**: full main text (pp. 1–19). I skimmed the proof of Lemma 4.1 (p. 15) and did not read the references.

- **D1 Problem & entry**: The entry is the cost of one iteration, not the number of iterations. Interior-point methods form and factor an m×m matrix with m = O(n²), which costs O(n⁶) operations and O(m²) memory (p. 1). The authors accept a method without polynomial complexity if each iteration is much cheaper (p. 1). The direct predecessor is the Schur-complement block coordinate descent (BCD) of Banerjee, El Ghaoui and d'Aspremont for sparse maximum likelihood (pp. 1–2).
- **D2 Core idea & algorithm design**:
  - Fix the (n−1)×(n−1) principal submatrix B of X. By the (generalized) Schur complement, X ⪰ 0 becomes ξ − yᵀB⁻¹y ≥ 0. This is a rotated second-order cone, so each row/column update is an SOCP (Thm 1.1, eqs. 2.4–2.6, pp. 2–4). Using ν > 0 instead of 0 on the right-hand side keeps the iterates positive definite (p. 4). One cycle updates rows 1..n (Algorithm 1, p. 5). The blocks overlap because X is symmetric (p. 5).
  - Maxcut SDP (diag X = 1): the subproblem has the closed-form solution y = −√((1−ν)/γ)·Bĉ, which costs one matrix-vector product (Lemma 3.1, p. 6; Algorithm 2 PURE-RBR-M, p. 7). A 3×3 example shows the failure with ν = 0. Started at a rank-one point, the method either stays put or moves to a non-optimal rank-one point and stays there (Table 3.1, pp. 6–7).
  - Lemma 3.2 reinterprets PURE-RBR-M as RBR on the log-barrier problem ⟨C,X⟩ − σ log det X, with ν a function of σ and γ (pp. 7–8).
  - General linear constraints: a 2×2 example shows RBR stuck at a non-optimal point (eq. 4.1, pp. 10–11). The fix wraps RBR in an augmented Lagrangian (AL), written as a quadratic penalty with a shifted right-hand side b^k. The PSD constraint stays out of the penalty (Algorithm 3, pp. 11–13). Each AL subproblem is an SOCP with two rotated cones (eq. 4.8, p. 12). For maxcut it reduces to the positive root of a cubic (eq. 4.10, p. 13). For nuclear-norm matrix completion it reduces to one linear system whose size is the number of sampled entries in the row (Lemma 4.1, p. 15; Algorithm 5, p. 16).
  - Unchanged: cyclic block coordinate descent (nonlinear Gauss–Seidel) and the classical augmented Lagrangian method (pp. 4–5, 11).
- **D3 Assumptions & model**:
  - Slater condition (Assumption 2.1, p. 3).
  - The convergence theorem covers the barrier problem with box constraints L ≤ X ≤ U and a convex f. Its proof uses strict convexity of ψ_σ and a compact level set (Thm 3.4, pp. 9–10).
  - Convergence of the AL version is argued from Theorem 3.4 plus the standard AL theory for strictly convex problems. It is not proved (p. 12).
- **D4 Analysis (brief)**: Theorem 3.4 (p. 9) states that every limit point is a global minimizer. The proof adapts Bertsekas's Prop. 2.7.1 in three steps (pp. 9–10):
  - The objective decreases monotonically across inner steps.
  - A contradiction argument, using strict convexity along a segment, shows X^{k,1} − X^k → 0 on a convergent subsequence.
  - The limit satisfies each row's variational inequality, and summing these entrywise gives global optimality.
  - The text calls the decreasing sequence *nondecreasing*, a misprint (p. 9). There is no rate.
- **D5 Experiments**: The maxcut tests use rudy graphs with n = 1000–4000, random (1 % density) and almost planar, five seeds each, with commands and seeds printed (p. 16). The baseline is DSDP 5.8 (dual interior point), compared on CPU time and cycles. Example R4000-1: DSDP takes 6274 s, and PURE-RBR-M takes 36.5 s (relative objective error 5.9e-3) or 261.1 s (4.0e-5) (Table 5.1, p. 18). Cycle counts barely grow with n (p. 17). Matrix completion uses p = q = 100–500, r = 10 and FR = 0.2/0.3, with seeds reported. No competing solver is run there, because DSDP is too slow (p. 18; Table 5.2, p. 19).
- **D8 Contribution & limits**: The contribution is an algorithmic framework with closed-form specializations and one convergence theorem.
  - Limits stated: the complexity is not polynomial (p. 1), and the experiments cover only two SDP classes (p. 15).
  - Future work: exploit the SOCP form of the AL subproblems (p. 12), and extend RBR to general conic programs with nonnegativity and second-order-cone constraints (p. 19).

**Method links**:
- Method 6 ✅ evidence (pp. 5–6, 13, 15): the constraint structure (a fixed diagonal, or sampled entries) turns each block subproblem into one matrix-vector product, one cubic root or one small linear solve. The generic SOCP subproblem is left unexploited (p. 12).
- Method 2 ⚠ variant (pp. 4–5, 10–13): classical BCD and AL are kept. But the change is a reformulation (PSD → SOC via the Schur complement), not the repair of a failing inequality under a weaker oracle.
- Method 2 ✅ evidence for step 4 (pp. 6–7, 10–11): each safeguard (ν > 0, the AL wrapper) comes right after a small counterexample that shows what fails without it.
- Methods 1, 3, 4, 5: no link (deterministic setting, no oracle, no complexity analysis, no estimator comparison).
- new-pattern candidate: **convergence by embedding in an existing framework** (p. 12; see batch synthesis).
- new-pattern candidate: **counterexample before safeguard** (pp. 6–7, 10–11).

**Transferable techniques**:
- To keep a PSD constraint inside block coordinate descent, fix the complementary principal submatrix. The block's feasibility then becomes a Schur-complement second-order-cone constraint (pp. 3–4).
- Justify each safeguard with the smallest counterexample that breaks the unguarded method (3×3 for ν = 0, 2×2 for coupled linear constraints), placed right before the safeguard (pp. 6–7, 10–11).
- Reinterpret a numerical safeguard parameter as a barrier parameter (ν ↔ σ). A convergence proof for the barrier problem then covers the practical algorithm (Lemma 3.2, pp. 7–8; Thm 3.4, p. 9).
- Print the instance-generator commands and the random seeds of every test problem (p. 16; Table 5.2, p. 19).

**Quotes**:
- "Although the computational complexity of the new method presented here is not polynomial, each of its iterations can be executed much more cheaply than in an interior point algorithm." (p. 1)
- "Fortuitously, the optimal solution of (3.2) is determined by a single matrix-vector product as we can see from the following lemma." (p. 5)

### S049 · SINCO-a greedy coordinate ascent method for sparse inverse covariance selection problem (preprint 2009, no DOI/arXiv)
**Role**: supplement · **Coauthors**: I. Rish (p. 1). The two are also coauthors of IBM Technical Report RC24812, cited as [13] (p. 21) · **Position in trajectory**: dated July 31, 2009 (p. 1). It is one of Scheinberg's 2009–2010 approaches to sparse inverse covariance selection, next to the alternating-linearization paper S010 (card in c01). It presents itself as a simplified RBR method (S048) applied to the primal problem (p. 5). S084 cites it as [15] (S084 p. 5). **Read**: full text (pp. 1–20). The figures are available only as axis labels and captions. References scanned.

- **D1 Problem & entry**:
  - The problem is to learn the zero pattern of Σ⁻¹, i.e. the structure of a Gaussian Markov network (pp. 1–3). The ℓ1-penalized maximum-likelihood problem (6) is generalized to an entrywise weight matrix S, so that different rows can carry different λ_i. This suits networks with very different node degrees (eq. 8, p. 4).
  - Entry: COVSEL and glasso apply row-wise BCD to the *dual* problem. Interior-point methods cost O(p⁶) per iteration and recover the sparsity pattern only in the limit, so numerical inaccuracy can interfere with structure recovery (pp. 4–5).
  - Algorithms are judged by structure recovery (true and false positives), not only by the objective value (pp. 1–2, 11).
- **D2 Core idea & algorithm design**:
  - Coordinate ascent on the *primal*. Each step changes one diagonal entry or one symmetric pair, so at most one or two nonzeros enter per step (p. 5). The absolute values are handled by splitting C = C′ − C″ with C′, C″ ≥ 0 (p. 6).
  - Given W = C⁻¹, det(C + θ(e_ie_jᵀ + e_je_iᵀ)) = det(C)(1 + 2θW_ij + θ²(W_ij² − W_iiW_jj)). The exact line search along each pair is therefore the root of a quadratic (eq. 10, pp. 7–8), and it costs a constant number of operations (p. 6).
  - Greedy (Gauss–Southwell) rule: evaluate all O(p²) candidate steps and take the one with the best objective improvement. Then update W by the Sherman–Morrison–Woodbury formula in O(p²) (Algorithm 1, p. 7; pp. 5, 9). One iteration costs O(p²), and the step computations parallelize (p. 9).
  - Changed relative to glasso and COVSEL: primal instead of dual, single entries instead of whole rows, greedy order instead of cyclic order (p. 5). Kept: exact coordinate-wise minimization (p. 9).
- **D3 Assumptions & model**: zero-mean Gaussian data (p. 3), and S ≥ 0 entrywise (p. 4). Convergence is asserted, not proved separately. The paper appeals to BCD on a strictly convex objective with only box constraints, and to the RBR convergence result of S048 (p. 9).
- **D4 Analysis (brief)**:
  - Step-length argument: the quadratic's discriminant is (na)² + 4b²W_iiW_jj > 0. Also f′(0) > 0, and f(θ) → −∞ as θ approaches θ_max = 1/(√(W_iiW_jj) − W_ij), where the argument of the log-determinant vanishes. So exactly one root lies in (0, θ_max) (p. 8).
  - A negative step is capped at −C′_ij (p. 9).
  - There is no rate.
- **D5 Experiments**:
  - Synthetic tests: random and scale-free (Barabási–Albert) networks with known ground truth, p = 100–1100 and n = 500–5500 (pp. 9–10, 13–15). The baseline is glasso, well-tuned Fortran code, while SINCO is a straight-forward C++ implementation (p. 13). Metrics: ROC curves (true/false positives) and CPU time.
  - fMRI data (StarPlus, three subjects, 40 samples, leave-one-out): SINCO against COVSEL and an SVM, on classification error, model density and time (pp. 15–17).
  - Tolerance path vs regularization path: the iterates of one run at λ = 0.01, stopped at tolerances from 1e-4 to 1e-7, reproduce the ROC curve of the regularization path over λ = 300 to 0.01 (pp. 11–13).
  - SINCO's CPU time scales better in p (Fig. 4, pp. 14–15).
  - As n grows with λ = log10(n), SINCO's false-positive rate falls toward 0 while glasso's grows, although glasso uses less CPU time (p. 15).
- **D8 Contribution & limits**: The contribution is an algorithm plus an empirical study.
  - Limits stated:
    - SINCO may miss true positives on denser networks (p. 5).
    - The regularization path costs less CPU time than the tolerance path (p. 12).
    - On sparse dual SDPs, such as the matrix-completion dual, the time to converge may be unacceptably large, and competitiveness is unclear (pp. 19–20).
  - Not discussed: because of the implementation gap, the CPU comparison mixes algorithm and code quality (p. 13).
  - Future work: apply RBR to (8) (p. 5); test other sparse SDPs (p. 20).

**Method links**:
- Method 6 ✅ evidence (pp. 5–9): a symmetric-pair update is rank two, so the determinant and the inverse update in closed form. One coordinate step then costs O(1), which makes a *greedy* choice over all p² pairs affordable.
- Method 5 ⚠ variant (pp. 9–15): the comparison is head-to-head against the state-of-the-art solver, on a metric tied to the real goal (ROC against the ground truth). It is not an equal-evaluation comparison, and the authors acknowledge that the CPU comparison is across unequal implementations (p. 13).
- Method 2 ⚠ variant (p. 5): coordinate descent is kept, but the change is the selection rule and the variable space (primal), not a repair.
- new-pattern candidate: **solver path as model-selection path**. The iterates of a greedy solver at one λ trace the same TP/FP trade-off as a regularization path, so early stopping can stand in for tuning λ (pp. 2, 11–12).
- new-pattern candidate: **convergence by embedding in an existing framework** (p. 9).
- Cross-batch: a synthetic testbed with known ground truth, like the s03 candidate *known-optimum testbed* (S073). Here it is used to measure recovery, not only the objective (pp. 9–10).

**Transferable techniques**:
- For log-det objectives, store W = C⁻¹ and apply det(C + uvᵀ) = det(C)(1 + vᵀC⁻¹u) twice. This gives a closed-form exact line search along any symmetric pair (pp. 7–8).
- If one coordinate step costs O(1), evaluate every candidate and take the best (Gauss–Southwell). The iteration still costs only the O(p²) of the rank-two inverse update (pp. 5, 9).
- When the goal is structure recovery, plot the ROC traced by one run's iterates at decreasing tolerance next to the ROC of the λ-path (Figs. 1–2, pp. 12–13).
- If the solution size changes with the tolerance, report CPU time per nonzero rather than raw CPU time (Fig. 3, p. 14).

**Quotes**:
- "But since the real goal is to recover true nonzero structure of the covariance matrix, it is not necessary to solve problem (8) accurately." (p. 12)
- "On the other hand, it may suffer from introducing too few nonzeros and thus missing some of the true positives, especially on denser networks." (p. 5)

### S123 · Efficient Algorithms for the Group Lasso (manuscript 2010, no DOI/arXiv)
**Role**: supplement · **Coauthors**: Z. (Tony) Qin and D. Goldfarb (Columbia IEOR, p. 1) · **Position in trajectory**: Scheinberg is at Lehigh (p. 1).
- **Version**: the file is titled *Efficient Block-coordinate Descent Algorithms for the Group Lasso* (Springer manuscript template, p. 1).
  - It cites 2011 work: Richtárik–Takáč, arXiv:1107.2848, and Rakotomamonjy 2011 (p. 21).
  - It says M-BCD appeared *while the first version of this paper was in preparation* (p. 12).
  - So it is a revision of the 2010 item, with the same authors.
- **Read**: full main text (pp. 1–21). I skimmed Appendix A (data-set details, pp. 22–23). The figures are absent apart from their captions.

- **D1 Problem & entry**: The problem is the Group Lasso, min ½‖Ax − b‖² + λΣ‖x_j‖ (eq. 1, p. 2).
  - Classical BCD (Yuan–Lin, Meier et al.) has closed-form block solutions only under the restrictive assumption A_jᵀA_j = I.
  - Friedman et al. drop that assumption but solve the blocks inexactly by coordinate descent (pp. 2–3).
  - Gradient methods (ISTA/FISTA, SLEP) have closed-form subproblems and good rates, but in practice they are often slower than BCD (p. 2).
- **D2 Core idea & algorithm design**:
  - **BCD-GL** minimizes each block exactly for a general A_j. The block solution is x_j = 0 if and only if ‖p_j‖ ≤ λ. Otherwise it solves a trust-region subproblem for some radius Δ: x_j = Δ·y_j(Δ) with ‖y_j(Δ)‖ = 1. Δ is found by Newton's method on the secular equation φ(Δ) = 1 − 1/‖y_j(Δ)‖, using one eigendecomposition of M_j = A_jᵀA_j computed at the start (eqs. 2–9, pp. 3–4; Algorithm 2.1, p. 4). Usually fewer than five Newton steps are needed. The positive solution rules out the trust-region *hard case* (p. 4).
  - **ISTA-MS** is ISTA with a fixed vector of block scalings t = θt̄, t̄_j = 1/‖A_j‖, and a line search on θ (p. 6).
  - **ISTA-BC** runs a separate backtracking line search for each block, in Gauss–Seidel order (Algorithm 4.1, p. 6).
  - **BCD-HYB** uses BCD-GL steps for groups of up to N_BC = 200 variables and ISTA-BC steps for larger groups (pp. 7, 13).
  - **Randomized variants**: block selection uniform or proportional to L_j, following Nesterov (p. 7).
  - **MMV**: written as a Group Lasso, the block Hessians are ‖A_j‖²I, so BCD-GL and ISTA-BC coincide in closed form (BCD-MMV, Algorithm 5.1, p. 12).
  - Implementation: incremental residual updates cost 1/J of a full product. The full residual is recomputed every J sub-iterations to prevent drift (p. 13).
- **D3 Assumptions & model**:
  - Least-squares loss.
  - The groups are given and do not overlap. Overlapping groups are handled by duplicating columns (p. 14).
  - If M_j is singular, M_j + δI is used so that the framework's uniform Hessian bounds hold (p. 10).
- **D4 Analysis (brief)**:
  - **Theorem 1** (pp. 8–9): ISTA-MS keeps ISTA's O(1/k) rate. The constant is proportional to √R_L, the square root of the ratio of the largest to the smallest block Lipschitz constant. The proof is Beck–Teboulle's with a vector L in place of the scalar (Lemma 1, p. 8), plus a lower bound on the unscaled step (p. 8). The last line of the proof carries an unexplained extra factor β in C (p. 9).
  - **Theorem 2** (p. 10): BCD-HYB converges globally. The proof shows that both step types are steps of Tseng–Yun's block coordinate gradient descent (BCGD) (pp. 9–10):
    - An ISTA-BC step is a BCGD step with H_jj = (1/t_j)I.
    - A BCD-GL step is a BCGD step with H_jj = M_j.
    - Both satisfy BCGD's modified Armijo rule with α = 1, σ = 1, γ = 1/2, and the uniform bounds θ̲I ⪯ H ⪯ θ̄I.
  - **Gap the authors state**: the ISTA/FISTA rate proofs do not carry over to ISTA-BC or BCD-GL (p. 7).
- **D5 Experiments**:
  - **Setup**: Matlab on a laptop.
    - Data: 11 small synthetic sets (Table 2, p. 14) and 7 large-group sets (Table 3, p. 15). Breast-cancer expression data with 878 overlapping pathway groups, which become 28,459 features after duplication (p. 14). MMV sets and scalability series (Tables 4–5, p. 15).
    - Baselines: FISTA, SLEP, their own BCGD, SpaRSA and SPG/SPOR-SPG (p. 13).
    - Stopping rule: every method stops at F(x) − F(x*) ≤ 1e-5, measured against a reference solution computed by ISTA-BC (p. 15).
    - Metrics: CPU time, iterations and fractional counts of matrix-vector products (Aprods), shown as Dolan–Moré performance profiles (p. 16).
  - **Results**: BCD-HYB and ISTA-BC clearly outperform FISTA and BCGD overall, but do much worse on the Nemirovski sets (p. 16). FISTA-BC and uniform randomization bring no gain. RBCD-GL with p_j ∝ L_j sometimes wins (pp. 7, 17; Table 6, p. 20).
  - **Caveat the authors flag**: Aprods leave out BCD-GL's eigendecomposition and Newton costs (p. 16).
- **D8 Contribution & limits**: The contribution is algorithmic, with an implementation. Limits stated:
  - There is no rate for ISTA-BC or BCD-GL (p. 7).
  - It is unclear whether acceleration helps in the block setting (p. 7).
  - Gauss–Seidel steps cannot run in parallel, and the Jacobi variant was slower (p. 6).
  - Performance is poor on Nemirovski's worst-case-style sets (p. 16).
  - The conclusion restates the results and gives no future work (p. 21).

**Method links**:
- Method 6 ✅ evidence (pp. 3–4, 12): block structure is exploited before any generic solver: one eigendecomposition per group, reused every iteration, and identity block Hessians in the MMV case.
- Method 2 ✅ evidence, variant (pp. 6, 9–10): ISTA is kept, and only the step-length rule changes (one per block). The convergence proof comes from showing that the new steps are instances of an existing convergent method (Tseng–Yun BCGD), not from a new analysis.
- Method 5 ⚠ variant (pp. 13–16): every solver runs to the same accuracy target against a common reference solution, and work is counted in matrix-vector products rather than time. But work is counted in Aprods, not function evaluations, and the eigendecomposition cost is excluded (p. 16).
- Methods 1, 3, 4: no link. The Moré–Sorensen trust-region secular equation is used to solve a lasso block (pp. 3–4), a small case of trust-region tools moving into another area.
- new-pattern candidate: **convergence by embedding in an existing framework** (pp. 9–10).
- new-pattern candidate: **explicit negative scope statement** (weak): the losses on the Nemirovski sets are reported (p. 16).

**Transferable techniques**:
- Solve a group-lasso block exactly by treating it as a trust-region subproblem. Find the radius by Newton's method on 1 − 1/‖y(Δ)‖, using an eigendecomposition cached once (pp. 3–4).
- To prove convergence of a hybrid of two step types, show that each type satisfies the acceptance rule and the Hessian bounds of an existing convergent framework (pp. 9–10).
- When a block-wise product is cheaper than a full one, count it as a fraction of a full product, so that work comparisons stay fair (p. 15).
- Stop all competitors at the same objective gap against a precomputed reference solution, and report performance profiles (pp. 15–16).

**Quotes**:
- "The proofs of the theoretical rates of convergence of the ISTA/FISTA algorithms do not readily extend to ISTA-BC or BCD-GL." (p. 7)
- "However, as we show in our computational results, the BCD approach (when it can be applied) often outperforms the existing gradient-based approaches." (p. 2)

### S035 · Block coordinate descent methods for semidefinite programming (Handbook on semidefinite, conic and polynomial optimization 2012, DOI 10.1007/978-1-4614-0769-0_19)
**Role**: supplement · **Coauthors**: Z. Wen (Shanghai Jiaotong) and D. Goldfarb (Columbia) (p. 1) · **Position in trajectory**: Scheinberg is at Lehigh (p. 1). This handbook chapter re-presents S048 (cited as [67], p. 32) and adds four things:
- a BCD literature review (pp. 2–5);
- BCD for the sparse inverse covariance dual (§3.3, pp. 13–14);
- a rank-two-update generalization (§5, pp. 21–23);
- new baselines: SDPLR, FPCA and SVT (pp. 23–26).

**Read**: I read §§1, 3.3, 3.4 (theorem statement), the end of 4.1, and 5–7. I compared §§2–4 with S048 and skimmed them where they are identical. References scanned (pp. 28–32).

- **D1 Problem & entry**:
  - The interior-point-cost entry is the same as in S048 (p. 2). It now comes with an explicit scope limit: BCD should not be used as a general-purpose SDP solver (p. 2).
  - RBR is placed in two surveys:
    - a survey of BCD methods (cyclic, essentially cyclic, Gauss–Southwell and randomized rules; convergence results from Bertsekas to Nesterov's RCDM, pp. 2–4);
    - a survey of first-order SDP methods. Most of these use augmented Lagrangians and differ in how they handle the PSD constraint (p. 5).
  - As far as the authors know, Banerjee et al. were the first to apply BCD to an SDP (p. 4).
- **D2 Core idea & algorithm design**:
  - The core RBR/Schur-complement construction, PURE-RBR-M and the AL versions are as in S048 (pp. 6–21).
  - **New (§3.3)**: the glasso and Banerjee BCD methods for sparse inverse covariance are derived as RBR on the dual problem max log det W s.t. ‖W − S‖∞ ≤ λ, which has only bound constraints. The row subproblem is a box-constrained QP whose dual is a Lasso (eqs. 28–33, pp. 13–14).
  - **New (§5)**: rank-two updates X⁺ = X + ½(uvᵀ + vuᵀ).
    - For a fixed u, positive definiteness of X⁺ is a single second-order-cone condition, 2 + uᵀX⁻¹v − √((uᵀX⁻¹u)(vᵀX⁻¹v)) > 0. It follows from the two nontrivial eigenvalues of I + ½(yxᵀ + xyᵀ) (eqs. 54–56, p. 22).
    - The AL subproblem in v is an SOCP (eq. 57, p. 23).
    - Suggested choices of u: e_i + e_j for sensor-localization constraints, blocks for clusters, or the leading eigenvector of the gradient (pp. 21–22).
  - Closed-form AL subproblems for the Lovász theta function are mentioned without detail (p. 21).
- **D3 Assumptions & model**:
  - **Theorem 3**: the compact level set is now an explicit assumption, and f must be differentiable and convex (pp. 14–15).
  - **AL convergence**: the chapter only says that a slightly modified version of Algorithm 2 converges, with details deferred to Wen's thesis (p. 19).
  - **Rank-two convergence**: said to extend easily for a finite spanning set of directions visited cyclically, or for an infinite set whose limit directions are finite and span Rⁿ. This is sketched, not proved (p. 23).
- **D4 Analysis (brief)**: Theorem 3's proof is the proof of S048's Theorem 3.4 (p. 15; compare S048 pp. 9–10). There is no new proof device. The rank-two cone condition comes from the eigenstructure of a rank-two perturbation of the identity (p. 22).
- **D5 Experiments**:
  - **Maxcut**: the table now includes SDPLR, a low-rank factorization code run with tolerance 2e-5 and parameter file p.maxcut5.
    - SDPLR reaches a relative objective error of 4.4e-6 to 6.9e-5 in 4.0–123.9 s.
    - PURE-RBR-M (ε = 1e-6) reaches 2.9e-5 to 4.9e-5 in 3.9–265.7 s.
    - DSDP takes 45.1–6310 s (Table 1, p. 25).
    - At about 5e-5 relative accuracy, RBR is called quite competitive with SDPLR (p. 24).
  - **Matrix completion** (p = q = 200–500) against FPCA and SVT:
    - FPCA is usually faster, except at p = q = 500 with FR = 0.3, where it took 20 to 35 times as long as RBR (p. 26).
    - SVT is reported only at its best parameters found (p. 26).
    - LMaFit is named as consistently much faster than all the methods (p. 26).
- **D8 Contribution & limits**: The chapter is a survey plus a generalization of the method.
  - **Limits stated in the summary** (p. 28):
    - RBR is first-order, so it is best when high accuracy is not needed.
    - Only constraints that do not couple blocks can be handled directly.
    - The AL wrapper helps even without coupling constraints, because it gives the method more freedom of movement.
    - Starting near the boundary of the cone with tight linear constraints can be very slow.
  - **On matrix completion** (p. 25): pure RBR gets trapped close to the boundary of the semidefinite cone.
  - **Open question** (p. 23): which rank-two directions to choose is left for further study.

**Method links**:
- Method 6 ✅ evidence (pp. 2, 21, 28): the summary states the scope rule directly. RBR suits problems whose block subproblem is closed-form or a simple QP (maxcut, matrix completion, theta functions, inverse covariance), and generic use is discouraged (p. 2).
- Method 5 ✅ weak evidence (pp. 24–26): stronger, specialized baselines are added (SDPLR, FPCA, SVT), and a faster competitor (LMaFit) is named although it wins. The comparison is on CPU time and accuracy, not on evaluations.
- Method 2 ⚠ variant (pp. 19, 28): the AL wrapper is the classical fix for BCD's inability to handle coupling constraints.
- Methods 1, 3, 4: no link.
- new-pattern candidate: **explicit negative scope statement**. State where the method should not be used, and name the faster competitor (pp. 2, 26, 28).
- new-pattern candidate: **convergence by embedding in an existing framework** (pp. 19, 23).

**Transferable techniques**:
- In the introduction, say in one sentence where your method should not be used, then show where it wins (p. 2).
- Generalize a coordinate update to a rank-two update X + ½(uvᵀ + vuᵀ). For a fixed u, positive definiteness is one second-order-cone constraint in v. The Cholesky factor updates in O(n²) through two rank-one updates (p. 22).
- When a competitor needs tuning, report that you tried many settings, which setting you used, and that it still did not work on every problem (p. 26).

**Quotes**:
- "We note, however, that using a BCD method as a general purpose SDP solver is not a good idea." (p. 2)
- "Like all first-order methods, they are best suited to situations where highly accurate solutions are not required." (p. 28)

### S085 · Aligning ligand binding cavities by optimizing superposed volume (2012 IEEE International Conference on Bioinformatics and Biomedicine 2012, DOI 10.1109/bibm.2012.6392629)
**Role**: supplement · **Coauthors**: R. Chen (Lehigh ISE) and B. Y. Chen (Lehigh CSE). Scheinberg and B. Y. Chen are co-corresponding authors (p. 1) · **Position in trajectory**: Lehigh period. This is the one DFO application in the batch. It uses the trust-region DFO framework of the Conn–Scheinberg–Vicente book (cited as [10], pp. 1–2). **Read**: full text (pp. 1–5). Figure 4 has no caption in the file, and Figure 1 survives only as axis ticks.

- **D1 Problem & entry**: The pull comes from the application.
  - Protein structure comparison superposes corresponding atoms (least-squares RMSD). But aligning atoms does not maximize the overlap of binding cavities, and it fails when the proteins lack atomic similarity (p. 1).
  - Problem: over rotations and translations, maximize the overlapping volume of two cavities. VASP computes this volume with Boolean set operations, which give values but no derivatives (p. 1).
  - The objective is noisy and non-smooth (Figure 1, p. 2).
  - Claimed payoff: if the largest possible overlap is smaller than a ligand, the ligand cannot bind in both cavities in the same conformation (p. 1).
- **D2 Core idea & algorithm design**: The method is model-based trust-region DFO from [10] (p. 2).
  - **The one change** is a dynamic accuracy strategy. VASP has a resolution r, with a noise estimate ξ_r. If the model reduction is comparable to ξ_r, the method lowers r (less noise) and rebuilds the model in the trust region (p. 2).
  - **Starts**: a warm start at the backbone superposition, or 10 Latin-hypercube starts, keeping the best result (p. 2).
  - **Kept**: the trust-region framework and its sufficient-reduction test (p. 2).
- **D3 Assumptions & model**:
  - The superposition is rigid (rotations and translations).
  - The trust-region framework is known to converge to a local optimum only when there is no noise. There is no global guarantee (p. 2).
  - The paper does not say how ξ_r is estimated (p. 2).
- **D4 Analysis (brief)**: none. The paper has no analysis.
- **D5 Experiments**:
  - **Data** (p. 3): 14 serine-protease and 10 enolase structures, filtered from 676 and 66 PDB entries.
  - **Baseline** (p. 3): backbone superposition by Ska. Dali and CE gave no significant differences.
  - **Evaluation**:
    - a visual orientation check: 124 of 136 superpositions are biochemically consistent (p. 3);
    - intersection volume compared with the backbone superposition (p. 4);
    - large-scale statistical tests of volumetric similarity and fragment volume at the 0.05 level (p. 4).
  - **Missing**: there is no optimizer baseline, and no evaluation counts or run times are reported.
- **D8 Contribution & limits**: The contribution is an application plus a small algorithmic adaptation.
  - **Limits stated**: 12 enolase pairs are misoriented, 6 at about 45° and 6 at about 90° (p. 3). The method finds local optima only (p. 2).
  - **Inconsistent volume claims**:
    - §4.2 says DFO-VASP beats the backbone superposition in all cases (p. 4).
    - The conclusion says similar or greater volume *In all but two cases* (pp. 4–5).
    - The abstract says *similar or occasionally larger* (p. 1).
  - **Future work**: applications to binding specificity and protein engineering (pp. 1, 5).

**Method links**:
- Method 1 ⚠ variant, early heuristic (p. 2): the accuracy of function evaluations is raised when the predicted decrease falls to the noise level. As in the oracle contract, accuracy is tied to the progress measure, but there is no probability and no analysis. This practice predates the probabilistic-model papers (S018, 2014).
- Method 2 ✅ evidence (p. 2): the classical trust-region DFO method is kept, and only the step that noise corrupts (the sufficient-reduction check) is repaired.
- Methods 3, 4, 5, 6: no link. Geometry is not discussed, and no competing optimizer is run.

**Transferable techniques**:
- If your simulator has a fidelity knob (resolution, sample size, mesh), raise the fidelity only when the model-predicted decrease is comparable to the current noise estimate. Then rebuild the model (p. 2).
- For a nonconvex application objective, run both a warm start from domain knowledge and a space-filling multistart (Latin hypercube), and compare their results (pp. 2, 4).

**Quotes**:
- "The essential mechanism of the above algorithm lies in the checking for the sufficient reduction, which is corrupted when the underlying function 𝑓 is computed with noise." (p. 2)
- "This algorithmic framework has been shown to converge to a local optimal solution in the absence of noise." (p. 2)

### S084 · Efficient quasi-newton proximal method for large scale sparse optimization (Conference on Neural Information Processing Systems (NIPS) 2013, no DOI/arXiv)
**Role**: supplement · **Coauthors**: X. Tang (Lehigh ISE, p. 1) · **Position in trajectory**: Lehigh period. This is a 5-page version of LHAC, the method analysed in S029 (Math. Program. 2016, card in c02) and S100 (arXiv 2013, card in s01). **Read**: full text (pp. 1–4) and the references (p. 5). The file has no conclusion section.

- **D1 Problem & entry**: The problems are ℓ1-regularized convex problems F = f + λ‖x‖1: sparse logistic regression, sparse inverse covariance and the Lasso (p. 1).
  - First-order methods have cheap iterations but slow local convergence and small steps (p. 1).
  - Second-order specialists (GLMNET, QUIC) are fast, but each exploits the Hessian structure of one loss (p. 1).
  - Entry: a general-purpose method that ignores the Hessian structure of f and still beats the specialists (p. 1).
- **D2 Core idea & algorithm design**: The framework builds a quadratic model plus the ℓ1 term, minimizes it approximately, and accepts the trial point on sufficient decrease. Otherwise it changes the model (pp. 1–2). Four changes:
  - **(i) Cheap coordinate steps**: the compact L-BFGS form B_k = γ_kI − QRQᵀ is used. By keeping v = Q̂d updated, one coordinate-descent step on the model costs O(m) instead of O(n) (eqs. 2.2–2.3, p. 2; §2.2, p. 3).
  - **(ii) Small working set**: the current nonzeros plus a few coordinates with the largest subgradient violation. GLMNET and QUIC take all violating coordinates (§2.1, p. 3).
  - **(iii) No line search**: if F(x + d) − F(x) ≤ ρ(Q_k − F(x)) fails, increase the prox parameter µ in H_k = B_k + (1/2µ)I and solve the subproblem again (eq. 2.5, p. 3).
  - **(iv) Inexact inner solves**: the number of coordinate-descent steps grows linearly with the outer iteration counter (p. 3).
- **D3 Assumptions & model**:
  - f is convex and twice differentiable, and g has an easy scaled prox (p. 1).
  - The theory is deferred: the authors *leave the theoretical analysis* of the general inexact scheme out of this paper (p. 2), and the citation for the rates is a broken `[?]` (p. 1).
  - The working-set rule is a heuristic outside the analysis (p. 2).
- **D4 Analysis (brief)**: none in this paper.
- **D5 Experiments**:
  - **Sparse inverse covariance**: C/C++ LHAC against QUIC on two gene-expression sets, Leukemia (p = 1255) and hereditarybc (p = 1869), with λ = 0.5.
  - **Sparse logistic regression**: LHAC against GLMNET on four sets: gisette, slices, connect-4 and a9a.
  - **Ablation**: LHAC against a line-search version of LHAC.
  - **Protocol**: x⁰ = 0, stop when ‖∂F(x_k)‖ ≤ 10⁻⁶‖∂F(x⁰)‖, plots of subgradient norm against time (pp. 3–4).
  - **Reported results** (p. 4):
    - about 30 % and more than 40 % faster than QUIC;
    - 2–4× faster than GLMNET, except on gisette, where the gap is within 0.5 s;
    - prox-parameter backtracking beats the line search.
- **D8 Contribution & limits**: The contribution is an algorithm plus software (the LHAC package, p. 3).
  - **Limits**: no theory in this paper, and a heuristic working set (p. 2).
  - **Draft-level issues**:
    - a broken citation (p. 1);
    - H_k is written as B_k + (1/2µ)I on p. 2 but as B_k + (1/µ)I on p. 3;
    - the line-search variant is LHAC-L in the text but LHAC-B in the legends of Figure 2 (pp. 3–4).
  - **Tuning note**: small values of ρ work much better than values near 1 (p. 3).

**Method links**:
- Method 6 ⚠ variant (pp. 1–3): the structure exploited is the low rank of the algorithm's own Hessian *approximation*, not structure in f. The paper stresses that it needs no problem structure (p. 1). It fits step 3 of Method 6 (low-rank or sparse structure that makes subproblems cheap), which SKILL.md already supports with Tang–Scheinberg 2016.
- Method 2 ⚠ variant (pp. 2–3): the classical line search is *replaced* by a trust-region-like prox-parameter update. The paper justifies the swap both by analysability and by performance (p. 3). This is the move of the c02 candidate *analysable surrogate for a practical heuristic* (S029), and here it is backed by an ablation (p. 4).
- Method 5 ⚠ variant (pp. 3–4): the comparison with specialist solvers is on time to a relative subgradient tolerance, not on evaluations.
- Methods 1, 3, 4: no link.

**Transferable techniques**:
- With a compact L-BFGS matrix B = γI − QRQᵀ, update v = Q̂d after every coordinate step. Then (Bd)_i = γd_i − q_iᵀv costs O(m) (p. 3).
- Replace a line search by increasing the prox term and solving the subproblem again. Accept with the ratio test F(x+d) − F(x) ≤ ρ(Q − F(x)). Then run an ablation against the line-search version (pp. 3–4).
- Build the working set from the current support plus the few largest violations of optimality (p. 3).

**Quotes**:
- "Instead of line search procedure, we update a prox term of our quadratic model, which allows us to extend global convergence bounds of proximal gradient methods to the case of proximal quasi-Newton methods." (p. 2)
- "In our experiments small values of ρ provided much better performance than values close to 1." (p. 3)

### S028 · Fast first-order methods for composite convex optimization with backtracking (Foundations of computational mathematics 2014, DOI 10.1007/s10208-014-9189-9)
**Role**: supplement · **Coauthors**: D. Goldfarb (Columbia) and X. Bai (Lehigh) (p. 1) · **Position in trajectory**: Lehigh period. The paper builds on Beck–Teboulle's FISTA and on FALM (Goldfarb–Ma–Scheinberg, S005, card in c01). It is the deterministic base of the 2025 stochastic ISTA/FISTA paper S068, whose card in c07 starts from FISTA-BKTR. **Read**: pp. 1–13 and 15–23. I skimmed FALM-BKTR (Algorithm 4.3) and the proof of Lemma 4.4 (pp. 14–15), and scanned the references.

- **D1 Problem & entry**: The entry is a proof assumption that is also a practical defect.
  - FISTA's analysis needs the prox parameters µ_k (inverse Lipschitz estimates) to be nonincreasing. One large early Lipschitz estimate therefore forces small steps from then on (p. 2).
  - The complexity bound depends on the smallest µ encountered (abstract, p. 1).
  - FALM with skipping steps uses a fixed µ (pp. 13–14).
- **D2 Core idea & algorithm design**:
  - **Kept**: FISTA's prox step and extrapolation, and Beck–Teboulle's key lemma (Lemma 2.3, p. 3).
  - **Changed**: the momentum recursion becomes t_{k+1} = (1 + √(1 + 4θ_k t_k²))/2 with θ_k = µ_k/µ_{k+1}. This keeps µ_k t_k² ≥ µ_{k+1} t_{k+1}(t_{k+1} − 1) even when µ grows (eqs. 3.11–3.13, p. 8).
    - µ_{k+1} is not known when t_{k+1} is computed. So every time backtracking lowers µ_k, the method also recomputes θ_{k−1}, t_k and y_k (the FistaStep call) before the next trial (Algorithm 3.5 FISTA-BKTR, p. 9).
    - FALM gets the same treatment, using the average µ_k = (µ_k^x + µ_k^y)/2 (Algorithm 4.3, p. 14).
  - **Why not simply take θ_k < 1**: then t_{k+1} < θ_k^{1/2}t_k + 1, so t_k stops growing at the rate the bound needs (p. 8).
  - **Local composite Lipschitz constant** L(f, g, y): a Lipschitz constant of ∇f on the segment [p_µ(y), y] (Definition 2.4, p. 4). Two examples show it can be much smaller than L(f):
    - the Lasso at a sparse point, where only the active columns matter (Example 2.5, p. 4);
    - Huber smoothing away from the kink, where L ≤ ‖AᵀA‖/(2‖Ay − b‖) (Example 2.7 and eq. 2.6, p. 5).
  - **Cost of backtracking**: for least squares, ∇f(y_k) is a combination of the two stored gradients. Each extra backtracking step therefore costs O(n) plus one matrix-vector product (pp. 11–12).
- **D3 Assumptions & model**: f is convex and C^{1,1} (Assumption 2.1, p. 2). g is convex with an easy prox (p. 1).
- **D4 Analysis (brief)**:
  - **Potential**: 2µ_k t_k² v_k + ‖u_k‖² is nonincreasing under (3.11) (Lemma 3.3, pp. 6–7). This gives v_k ≤ ‖x⁰ − x*‖²/(2µ_k t_k²) (Theorem 3.4, p. 7).
  - **Key lemma**: with θ_{k−1} = µ_{k−1}/µ_k, an induction on √µ_{k+1} t_{k+1} ≥ √µ_{k+1}/2 + √µ_k t_k gives µ_k t_k² ≥ (Σ_{i≤k} √µ_i / 2)² (Lemma 3.7, pp. 9–10).
  - **Results**:
    - O(L(f)/(βk²)) (Theorem 3.8, p. 10).
    - The same bound with L(f) replaced by an average of the local composite constants L(f, g, y_i) along the iterates, averaged in the square-root sense, provided each trial µ starts at 1/L(f, g, y_i) or above (Theorem 3.9, p. 10).
    - For FALM-BKTR, the bound is in terms of the average √µ_i (Theorem 4.6, p. 16).
  - **Backtracking count**: with a starting value µ⁰_k = µ_{k−1}/α and α = β, Nesterov's counting lemma gives an average of 2 FistaStep calls per iteration (Lemma 3.10, p. 11).
  - **Misprints**:
    - The text gives η = βL(f)/4 (p. 10), but the bound (3.15) corresponds to η = β/(2L(f)).
    - Theorem 4.5 refers to Algorithm 3.5 where Algorithm 4.3 is meant (p. 16).
- **D5 Experiments**:
  - **Problems** (pp. 17–22): the Lasso/compressed-sensing problem on Spear10, Spear3, Nemirovski's Bdata1 and Sparco3; a Huber-smoothed ℓ2 variant; and ℓ2-regularized logistic regression on Optdigits.
  - **Protocol** (p. 17): run FISTA for j iterations and record the best value FISTA(j). Then report how many iterations and matrix-vector products each method needs to go below it.
  - **Other baselines**: SpaRSA and YALL1 at default settings, *to gauge the difficulty* of the problems (p. 17). The µ trajectories are plotted (Figs. 5.1–5.4).
  - **Results**:
    - Example: on Spear3, final FISTA needs 28,517 iterations and 57,045 products, FISTA-BKTR 3149 and 6767 (Table 5.3, p. 19).
    - Failures are reported: SpaRSA fails twice, and FALM-BKTR slows down near the solution on Spear10 with ρ = 0.01 (pp. 18–19).
    - FISTA-BKTR can lose at early checkpoints (Table 5.3, p. 19; Table 5.8, p. 22).
- **D8 Contribution & limits**: The contribution is theory plus an algorithm. Limits stated:
  - Turning the average-local-constant bound into a concretely better bound needs an analysis of the iterates. This is left for future work (p. 22).
  - How to choose µ increases from estimated local Lipschitz changes is open (p. 11).
  - The rule of increasing µ every l iterations is a heuristic, with l tuned during the first 100 iterations (p. 12).
  - The local Lipschitz analysis for logistic regression is future work (p. 22).

**Method links**:
- Method 2 ✅ evidence (pp. 2, 8–9): FISTA and FALM are kept. The proof is rerun, and the first property that breaks when µ may increase, inequality (3.11), is repaired by coupling θ_k to the µ ratio inside backtracking. S068 (c07) later reuses exactly this repair as its deterministic base.
- Method 3 ⚠ variant, deterministic precursor (pp. 9–10, 16): the complexity is expressed through the trajectory of the step parameter (Σ√µ_i). This is Heuristic 10 (lower-bound the step parameter, then convert the bound into total cost) in deterministic form, before the stochastic-process versions.
- Method 5 ⚠ variant (p. 17): every method is held to the same accuracy target at each checkpoint (FISTA(j)), and work is counted in matrix-vector products. There are no function-evaluation counts and no noise.
- Methods 1, 4, 6: no link.
- new-pattern candidate: **counterexample before safeguard** (p. 8): before the full design, the paper shows that the simple fix (θ_k < 1) fails.

**Transferable techniques**:
- If an accelerated method needs a monotone step parameter, put the ratio θ_k = µ_k/µ_{k+1} into the momentum update. Recompute the extrapolated point every time backtracking lowers µ. The invariant µ_k t_k² ≥ µ_{k+1}t_{k+1}(t_{k+1} − 1) then holds by construction (pp. 8–9).
- Prove µ_k t_k² ≥ (Σ√µ_i/2)² by induction. The rate is then expressed through the average of √µ_i, not the worst µ (pp. 9–10).
- Benchmark protocol: run the baseline for j iterations and take its best value as the target. Then report each competitor's iterations and matrix-vector products to reach that target (p. 17).
- Plot the step-parameter trajectory next to the tables to show why one method needs fewer iterations (Figs. 5.1–5.4, pp. 18–23).

**Quotes**:
- "The principal drawback of FISTA compared to the method in [9] is the requirement that the estimates of the Lipschitz constant (or the prox parameters) that are used must be nondecreasing from one iteration to the next." (p. 2)
- "Ideally, one should select the increase of the prox term based on the estimated increase of the local Lipschitz constant." (p. 11)
