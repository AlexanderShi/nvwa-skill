# Paper cards · batch s2-01 (supplement)

**Batch intent**: s2-01 collects eight supplement items from 2000–2007, Scheinberg's doctoral and IBM Watson years, well before the stochastic-oracle work of 2014 onwards. They are: a DFO software manual (S133), the Λ-poisedness error-bound preprint (S072), two interior-point linear-algebra papers with Goldfarb (S050, S058), a parametric-QP SVM training paper (S059), two applied IBM collaborations (S086 video events, S102 seismic inversion), and a BIRS workshop report on optimization in ML (S129). The question: which of the skill's Methods are already visible in this early work, especially Method 4 (geometry is the price of model-based DFO) and Method 6 (exploit structure)? Does the "error ≤ κ·Δ" shape of the Method 1 contract come from the deterministic interpolation theory? And what does the non-DFO numerical linear algebra add (stability claims, counterexamples, cost models)?

### S133 · Manual for Fortran Software Package DFO v1.2 (— 2000, no DOI) — UNREADABLE as named; substitute text = DFO v2.0 manual (2003)
**Role**: supplement · **Coauthors (as listed)**: A. R. Conn, Ph. L. Toint; the file's author line is "K. Sheinberg" only (p. 1) · **Position in trajectory**: Conn–Scheinberg–Toint's trust-region interpolation code from 1996–98 (refs [1]–[4], pp. 12–13), here in a 2003 revision. The revision adds an IPOPT interface (p. 2) and cites the Conn–Scheinberg–Vicente preprint (= S072) for well-poisedness (ref [5], p. 3, p. 13). **Read**: the whole 13-page v2.0 text. v1.2 was **not read**, and nothing below should be attributed to it.

- **D1 Problem & entry** (v2.0): DFO is meant for smooth functions that are expensive to evaluate and whose derivatives are "unavailable and not desirable to approximate", with a relatively low dimension (< 50) (p. 1). The manual states when *not* to use it: when derivatives can be evaluated or estimated efficiently, or when n is high (p. 1). It handles three kinds of constraints. "Easy" constraints are cheap bounds, linear and smooth nonlinear constraints (p. 1). "Difficult" constraints are expensive black-box constraints computed in the same call as f (pp. 1–2). "Virtual" (hidden) constraints are handled through evaluation-failure flags (p. 1).
- **D2 Core idea & algorithm design** (v2.0): The base point is the best sample. The interpolation set is built from the samples closest to the base "while maintaining well-poisedness". The model is minimised over the trust region subject to the constraint models, or through an exact penalty function if that subproblem is infeasible. A ratio test then accepts the point or improves the model (pp. 2–3). Incomplete interpolation uses minimum-Frobenius-norm models by default (VARNT = 1). The alternative uses models built from Newton polynomials. The manual says the default "generally works better" (p. 9). By default, difficult constraints are modelled like the objective (METHOD = 1). Penalty variants exist for degenerate or nearly infeasible cases (p. 10).
- **D3 Assumptions** (v2.0): Smoothness is needed for the theoretical convergence guarantee. The code "may still be" appropriate if f is relatively smooth near the optimum (p. 1). The user may give absolute and relative noise levels (ANOISE, RNOISE), which are used only to stop promptly below the noise threshold (p. 8).
- **D4 Analysis (brief)**: None (a manual). The geometry machinery is exposed as parameters. PIVTHR (0.001) is the pivot threshold for accepting a point into the interpolation set. ADDTHR (0.1) is a stricter threshold for points that gave no reduction (p. 8). XCHTHR sets the pivot-improvement factor for a point exchange (pp. 8–9). EFFORT has four levels of how often the interpolation set is recomputed, from "only when necessary" up to "every time". The manual says the effect of these levels is "not fully tested yet" (p. 9). LAYER trades completeness of the model against up-to-dateness (p. 9). DELMAX = 10·DELTA stops large steps that would make old samples irrelevant (p. 7).
- **D5 Experiments**: none.
- **D8 Contribution & limits** (v2.0): The contribution is software. The limits are stated concretely: n < 50 by default and slow for large n (pp. 1, 7), effort levels untested (p. 9), and penalty METHOD 3/4 must not be used with IPOPT (p. 10). No future work is stated.

**Method links** (substitute text only):
- Method 4 ✅ evidence (pp. 8–9): geometry control is a set of tunable, paid-for knobs. They are pivot thresholds, point exchanges only when they improve the pivot, and an EFFORT scale whose lowest level recomputes the set "only when necessary". NPMIN = n+1 is described as guaranteeing "fully linear" models (p. 9).
- Method 6 ✅ evidence (pp. 1–2, p. 10): expensive constraints computed in the same call as f are modelled one by one, not folded into a penalty, and this is the default and "usually the most efficient" choice (p. 10). This fits Method 6 step 1 (model the components of a vector-valued black box).
- Method 1 ⚠ variant, early form (p. 8): the noise level enters only as a stopping rule ("avoiding computations below the noise threshold"). No accuracy requirement tied to Δ is stated. This is the Workflow B step 6 idea without the rest of the contract.
- new-pattern candidate: scope statement up front — the software says when not to use it (derivatives available, large n) (p. 1).

**Transferable techniques**:
- For hidden constraints in black-box optimisation, return an evaluation-failure flag rather than an artificially high function value. The manual warns that the latter makes the method inefficient and unstable (p. 1).
- Use two pivot thresholds: a loose one for points that made progress and a strict one for points kept only because they were already evaluated (PIVTHR 0.001 vs ADDTHR 0.1, p. 8).
- Cap the trust-region radius at a multiple of its initial value (DELMAX = 10·DELTA) so that one long step does not throw away the stored sample set (p. 7).

**Quotes** (from the v2.0 text):
- "For example, if NPMIN is n + 1 then every interpolation will be at least fully linear (if at all possible)." (p. 9)
- "Experiments and some intuition show that VARNT= 1 generally works better than VARNT= 2, but it may not be so for some problems." (p. 9)

### S059 · Incremental learning and selective sampling via parametric optimization framework for SVM (Advances in NIPS 14, 2001, DOI 10.7551/mitpress/1120.003.0095)
**Role**: supplement · **Coauthors**: S. Fine (IBM Watson) · **Position in trajectory**: IBM period. It is one of the SVM-training papers beside Fine–Scheinberg JMLR 2001 (low-rank kernels, SKILL Method 6). The detailed algorithms and lemmas are deferred to the POKER technical report (footnote 3, p. 2; ref [5], p. 7). The active-set SVM line continues in Scheinberg JMLR 2006, cited in S129 (p. 12, ref [17]). **Read**: full (7 pages). The figures survive only as garbled axis labels (p. 6).

- **D1 Problem & entry**: SVM training scales with the training-set size. Active-set methods converge but may be slow and need many passes over the data (p. 1). The common workaround fixes the bias, or adds it as a feature, to drop the linear constraint. This allows one-multiplier incremental updates, but generalises worse and gives more support vectors (pp. 1–2). The only exact incremental method for the 1-norm soft-margin SVM is Cauwenberghs–Poggio (p. 2). The authors enter from optimization: parametric QP, which is based on the simplex method (p. 2).
- **D2 Core idea & algorithm design**: POKER moves a scalar parameter in the right-hand side of the KKT system and maintains the optimal partition (I₀, I_c, I_s) along the way (p. 3). There are two instances. The fixed-bias method follows the homotopy u: 0 → 1 in system (3), starting from a trivially feasible point. The adjustable-bias method moves b monotonically until yᵀα changes sign (pp. 3–4). Alternating the two gives the incremental AltPOKER, which accepts increments of any chunk size (Figure 1, p. 5). Selective sampling ranks candidates by one of three criteria. Cls2W picks the point closest to the hyperplane. MaxSlk picks the most violating point. dObj runs a few iterations of the adjustable-bias method to estimate the objective change, which the paper likens to strong branching (p. 6).
- **D3 Assumptions**: The problem is the 1-norm soft-margin SVM with its KKT system (p. 2–3). Two cases are distinguished. If Q_ss is nonsingular (nondegenerate), α_s is linear in b. If Q_ss is singular (degenerate), the solution set moves linearly while the partition stays optimal (p. 4). The O(n²) total estimate assumes few support vectors (p. 7).
- **D4 Analysis (brief)**: Finite termination: each iteration covers a b-interval with its own optimal partition, and there are finitely many partitions (p. 4, citing Berkelaar et al. and Rockafellar). The cost of a nondegenerate iteration is O(n|I_s|) + O(|I_s|³). A degenerate iteration costs O(n²|I_s|²) in theory and O(n|I_s|²) "in practice" (p. 4). The worst case is exponential, as for simplex, and is argued not to occur in practice (p. 2, p. 5).
- **D5 Experiments**: Batch mode: iterations vs size on Abalone (up to 4177 points), polynomial kernels of rising degree (p. 5). Incremental: diabetes with an RBF kernel as in Cauwenberghs–Poggio, iterations vs chunk size (pp. 5–6). Selective sampling: AltPOKER iteration counts on synthetic 10K×2, ionosphere and diabetes (Table 1, p. 7). All counts are iterations only, with no timing. The comparison with Cauwenberghs–Poggio is qualitative ("a similar scale", p. 6). Table 1 shows that MaxSlk alone is worse than no selection on diabetes (3860 vs 3078 iterations, p. 7). The text does not comment on this.
- **D8 Contribution & limits**: An algorithmic framework with finite convergence (p. 7). Stated limits: exponential worst case (p. 2) and a complexity estimate that depends on few support vectors (p. 7). Future work: a true on-line version, active learning, massive-data (speech) applications (p. 7).

**Method links**:
- Method 2 ✅ evidence, pre-DFO (p. 2, p. 6): the authors keep a classical optimization device (parametric QP / simplex-type pivoting on partitions) and carry it into SVM training instead of inventing a bespoke solver. The dObj criterion reuses strong branching from integer programming (p. 6).
- Method 6 ✅ evidence (pp. 3–4): the method exploits the fact that the KKT solution is piecewise linear in one scalar (b or u) while the partition is fixed.
- Method 5 ⚠ variant (pp. 5–7): comparisons count iterations and are not run head-to-head at equal cost. This is the pattern Method 5 warns against, in an early ML paper.
- new-pattern candidate: classical OR device imported into ML — parametric programming and strong-branching look-ahead brought into SVM training (p. 2, p. 6). Compare the "reverse field import" candidate from s01/S033.

**Transferable techniques**:
- To solve a problem with one awkward coupling constraint, first solve the relaxed problem with that parameter fixed. Then treat the parameter as a homotopy variable and track the optimal partition until the dropped optimality condition holds (pp. 3–4).
- Use a few iterations of the exact solver as a cheap look-ahead score for picking which data to add next, after a cheaper criterion has shortlisted the candidates (p. 6).
- For finite termination of a partition-following method, show that each iteration consumes one parameter interval with a distinct optimal partition (p. 4).

**Quotes**:
- "In theory adding even one point may force the algorithm to work as hard as if it were solving the problem "from scratch". But in practice it virtually never happens." (p. 5)
- "Our method is independently developed, but somewhat similar to that in [3]." (p. 7)

### S072 · Error estimates and poisedness in multivariate polynomial interpolation (Centro de Matemática da Universidade de Coimbra, Preprint 03-09, 2003, no DOI)
**Role**: supplement · **Coauthors**: A. R. Conn, L. N. Vicente · **Position in trajectory**: Written while Vicente visited IBM Watson (p. 1). The paper introduces Λ-poisedness, the geometry measure behind the Conn–Scheinberg–Vicente poisedness line cited under Method 4 in SKILL.md. It also revisits the authors' own 1997 convergence analysis (p. 26–27). The DFO v2.0 manual (S133 substitute) cites it for well-poisedness. **Read**: partial. Read: §1, §2 in full (definition, Lemmas 2.2–2.3 with proofs, Theorem 2.4 with proof, §2.3), §3 statements (Definition 3.1, Lemma 3.2 and the start of its proof, Lemma 3.3 with the start of its proof, Theorem 3.4 statement and first proof step), §5, §6 and §7. **Not read**: the §3.2 derivation details (pp. 13–15), §4 on cubic interpolation (pp. 21–23), and the end of §6.2 (p. 31).

- **D1 Problem & entry**: Interpolation models replace Taylor models in derivative-free trust-region methods. Standard convergence theory can then be used only if the models have Taylor-like error bounds (pp. 1–2). The existing bounds (Powell, Sauer–Xu, Waldron) are tied to Lagrange or Newton bases and are hard to interpret. Waldron is hard to follow for optimizers. Powell bounds only function values, not derivatives (p. 2). The condition number of the interpolation matrix depends on the basis and "can also be misleading" (p. 6). The entry point is a geometric, basis-independent condition on the sample set.
- **D2 Core idea**: Λ-poisedness asks that, for every x in B(Δ), φ(x) − φ(0) be a combination of the φ(yⁱ) − φ(0) with coefficients of norm ≤ Λ (Definition 2.1, pp. 6–7; Definition 3.1, p. 12). The definition is basis-independent by Lemma 1.1 (p. 4, p. 7). It means the points form a "fat" simplex (p. 7), and it is equivalent to bounded Lagrange polynomials up to a factor (p−1)^{1/2} (Proposition 5.2, p. 24). All derivative errors come from one linear system, and the function-value error is derived afterwards (p. 1, p. 32). Algorithm 6.1 builds or repairs the set by Gaussian elimination with a pivot threshold ξ < 1/2. A point whose pivot polynomial is too small is replaced by that polynomial's maximiser in the unit ball (pp. 27–28).
- **D3 Assumptions**: Y ⊂ B(Δ), with one interpolation point at the centre. The authors note that this is exactly the trust-region situation, where the centre is the best point so far, and that shifting doubles some constants (pp. 3–4). Linear case: n+1 points, ∇f Lipschitz with constant γ_L (p. 5). Quadratic case: (n+1)(n+2)/2 points, ∇²f Lipschitz with constant γ_Q (pp. 11–12). Λ-poisedness is scale-invariant for linear interpolation but not beyond (p. 7).
- **D4 Analysis (brief)**: Subtract the interpolation conditions pairwise and Taylor-expand around x. This gives L e_g(x) = O(Δ²), with a matrix L that does not depend on x (eq. (10), p. 8). ΛL-poisedness ⇔ ‖L⁻¹‖ ≤ Λ/Δ, by scaling to the unit ball (Lemmas 2.2–2.3, pp. 9–10). Theorem 2.4 follows: ‖e_g‖ ≤ (5√n γ_L Λ_L/2)Δ and |e_f| ≤ (5√n γ_L Λ_L/2 + γ_L/2)Δ² (p. 10). In the quadratic case the Hessian error is O(Δ), the gradient error O(Δ²) and the function error O(Δ³). The constants are ∝ (p−1)^{1/2} θ_Q γ_Q Λ_Q (Theorem 3.4, p. 19). θ_Q comes from Lemma 3.3: a quadratic with ‖v‖∞ = 1 attains |value| ≥ 1/2 on the unit ball. The proof restricts to the variables of the largest coefficient (pp. 17–18). The same lemma justifies ξ < 1/2 in Algorithm 6.1 (p. 28). Algorithm 6.1 costs O(n⁶) flops (p. 29). §5.3 explains why derivative bounds cannot simply be read off function bounds (pp. 26–27).
- **D5 Experiments**: none.
- **D8 Contribution & limits**: Theory plus a geometry-repair algorithm. In the linear case the optimal geometry is y^i = e_i, with Λ_L = 1 (§6.2, p. 30). The limits are stated as open choices. It is "unclear" whether the pairwise-difference bound (13) beats (12) (p. 11). The growth factors in ‖L⁻¹‖‖U⁻¹‖ are only "expected to be of reasonable size for most practical instances" (p. 29). The conclusion lists no future work (pp. 31–32).

**Method links**:
- Method 4 ✅ strong evidence (p. 2, pp. 27–28, p. 32): geometry is the only controllable source of model error, and Λ measures its price. Algorithm 6.1 replaces only the "bad" points (p. 27). This is the theoretical base of the minimal-geometry lens.
- Method 1 ✅ evidence, origin of the form (p. 10, p. 19): model errors are bounded as constant × Δ^k. The constant has a controllable part (Λ) and an uncontrollable part (γ). This is the "error ≤ κ·Δ" shape that the later probabilistic contract requires only with probability p.
- Method 2 ✅ evidence (p. 2): the goal is to let "the standard unconstrained optimization convergence theory" apply unchanged, by giving interpolation models Taylor-like properties rather than designing a new method.
- new-pattern candidate: equivalence-bridge definition — introduce a more intuitive quantity, then prove it equivalent (up to a constant) to the established one, so that prior results transfer (p. 2, Proposition 5.2, p. 24). Compare s01/S053, where the new partial RIP is implied by the classical RIP with the same constant.
- new-pattern candidate: self-correction of own earlier analysis — §5.3 shows that the 1997 Conn–Scheinberg–Toint bound (O(Δ) gradient error under bounded Hessians) "can only provide global convergence to first-order critical points" (p. 27).

**Transferable techniques**:
- To bound all derivative errors of an interpolation or regression model at once, subtract the interpolation conditions from each other so that the unknown function-value error cancels. Then invert the resulting x-independent matrix. Derive the function-value error last (pp. 8–10, p. 32).
- Define a geometry quality measure through the coefficient norm of representing any point by the sample points, prove that it is basis-independent, and tie it to ‖L⁻¹‖ by rescaling to the unit ball (pp. 7, 9–10).
- Turn a threshold-pivoting Gaussian elimination into a geometry-repair routine: when pivot k is small, replace point k by the maximiser of the pivot polynomial. A universal lower bound (here 1/2) makes the threshold always attainable (pp. 28–29).

**Quotes**:
- "However, it turns out to be equivalent to Λ being the upper bound on the absolute values of the Lagrange polynomials." (p. 2)
- "In practical situations only the geometry of the interpolation set is controllable." (p. 32)

### S050 · A product-form Cholesky factorization method for handling dense columns in interior point methods for linear programming (Mathematical Programming 2004, DOI 10.1007/s10107-003-0377-7)
**Role**: supplement · **Coauthors**: D. Goldfarb · **Position in trajectory**: This paper comes from Scheinberg's doctoral research (footnote: "the doctoral research of this author was supported in part by an IBM Cooperative Fellowship", p. 1). The manuscript is dated December 16, 2002 (p. 1). It is extended to SOCP in S058. **Read**: partial. Read: abstract, §1, §2 (including the Schur-complement counterexample, pp. 4–6), §3 up to Procedure 1 (pp. 7–10), §4 opening, Lemmas 4.1–4.3 with proofs, Theorem 4.4 statement and the start and end of its proof, Theorem 4.5 with proof, the first pages of §4.2, §4.3 opening only, §5 opening and the statements of Theorems 5.1–5.3, the §6 cost paragraph (p. 27), and §7 in full. **Not read**: the §4.3 error-analysis details (pp. 19–21), the §5 proofs, the §6 implementation details (pp. 26, 28), and the middle of the Theorem 4.4 proof (p. 13).

- **D1 Problem & entry**: Cholesky factorization of the normal equations AD²Aᵀ is the standard IPM linear solve, but dense columns cause massive fill-in (pp. 1–2). The popular remedy, Sherman–Morrison–Woodbury / Schur complement, is efficient but unstable when A_sD_s²A_sᵀ is (nearly) rank-deficient, which is likely near optimality. A 2×2 example shows it returning a solution "not even close" (pp. 5–6). Andersen's fix with artificial identity columns is also unstable. In the authors' runs this happened on about half of the test problems in the last iterations (p. 6).
- **D2 Core idea & algorithm design**: Factor the sparse part as LΔLᵀ. Then add each dense column as a symmetric rank-one update, kept in product form L L̃₁…L̃_k Δ̃_k L̃_kᵀ…L̃₁ᵀ Lᵀ (Procedure 1, pp. 7–10). The normal-equations approach, the IPM and the sparse Cholesky stay unchanged. Only the dense-column treatment changes. Small pivots are handled by a pivot-skipping variant that extends Wright's modified Cholesky (§5, p. 22).
- **D3 Assumptions**: A is fixed and D is diagonal, depending on the duality measure μ. Near-degeneracy is assumed not to occur (p. 10). The IPM iterates follow the optimal-partition rates, x_i = Θ(1) and s_i = Θ(μ) on B, and conversely on N (pp. 10–11). The error analysis follows reference [7] (p. 18).
- **D4 Analysis (brief)**: Theorem 4.4: for fixed A, the unit lower-triangular Cholesky factor of AD²Aᵀ has entries uniformly bounded as μ → 0, for any diagonal D (p. 12). The proof assumes blow-up and takes the smallest column index k where it occurs. A subsequence-partition lemma sorts functions by their rates (Lemma 4.1, p. 11), and a projection lemma forces linear dependence (Lemma 4.3, p. 12), which gives a contradiction (pp. 12–14). The paper relates the result to the Vavasis–Ye weighted least-squares constant χ_A (p. 10). Theorem 4.5 carries boundedness to the product-form factors through uniqueness of the factorization and Lemma 4.2 (p. 14). With pivot skipping, the computed step satisfies ‖Δ^{1/2}Lᵀ(x − x̄)‖ ≤ O(δ)‖x‖ (Theorem 5.3, p. 25). A cost model predicts about 4% more work than Schur complement when k ≈ 10 and m ≈ 3000, and up to about 50% when k = 50 (p. 27).
- **D5 Experiments**: 20 problems: 5 Netlib problems and deterministic equivalents of two-stage stochastic LPs with 4–50 dense columns (Table 1, p. 30). Four solves (regular Cholesky, PFCF, Schur complement with Andersen's columns, augmented system) run inside Mehrotra's fo1/fo1aug. OSL is timed, and CPLEX 6.5.1 is checked for stability only. Settings: accuracy 10⁻⁸, skipping tolerance 10⁻¹² (pp. 29–30, p. 32). Failures are marked "*" (accuracy not reached) and "-" (out of memory) in Table 3 (p. 33). A separate check of factor-entry sizes on seba shows Θ(1), Θ(μ²) and Θ(μ⁴) peaks (p. 16).
- **D8 Contribution & limits**: Algorithm, theory and computation. The conclusion concedes speed. PFCF is "slightly inferior" to Schur complement in speed. The augmented-system method is up to three times faster when there are many dense columns (p. 34). Implementation differences between the two host codes are acknowledged (p. 29). Future work: extend Theorem 4.4 to other D classes and to IPMs for general convex problems, "in a forthcoming paper" (p. 34). That paper is S058.

**Method links**:
- Method 2 ✅ evidence, pre-DFO (pp. 2, 7, 22): keep the method practitioners trust (normal equations + sparse Cholesky). Replace only the step that breaks (dense-column handling), using a classical rank-one update and Wright's pivot-skipping analysis.
- Method 6 ✅ evidence (pp. 5, 7): the matrix is split into a sparse part and a low-rank dense part, and each part is treated with the tool that suits it.
- Method 5 ✅ evidence, linear-algebra form (pp. 29–34): competing solves run inside the same IPM code and test set. Failures are reported. Stability and speed are measured separately (CPLEX for stability only, OSL for time only, p. 32).
- Research Taste mark 5 ✅ (pp. 5–6, p. 34): a small negative example shows why the fast competitor cannot be trusted, and the paper then pays a measured speed cost (about 4% by the cost model) for stability.
- new-pattern candidate: tiny explicit counterexample — a 2×2 instance where the competitor fails in floating point, placed before the new method (pp. 5–6). S058 §5 has a sibling example that marks the boundary of a theorem.
- new-pattern candidate: stability as uniform boundedness in the limit — prove that factor entries stay bounded as the barrier parameter → 0, by a contradiction at the smallest bad index along a subsequence (pp. 11–14; reused in S058).

**Transferable techniques**:
- To argue that a fast method is numerically unsafe, build a 2×2 or 3×3 instance where a quantity below machine precision destroys the answer. Show the computed and exact solutions side by side (pp. 5–6).
- To prove that entries of a parameter-dependent factorization stay bounded, assume the contrary and pick the smallest column index that blows up, so that all earlier columns are bounded. Pass to a subsequence where every scale ratio converges, and derive a linear dependence that contradicts the setup (Lemmas 4.1–4.3, Theorem 4.4, pp. 11–14).
- Give an operation-count model in the problem's own sizes (k dense columns, m rows) that predicts the relative slowdown, and check it against timings (p. 27, Table 3, p. 33).

**Quotes**:
- "But the main property holds for all tested examples: the elements of L do not grow." (p. 18)

### S058 · Product-form Cholesky factorization in interior point methods for second-order cone programming (Mathematical Programming 103(1), 153–179, 2005, DOI 10.1007/s10107-004-0556-1)
**Role**: supplement · **Coauthors**: D. Goldfarb · **Position in trajectory**: The direct sequel to S050 (its ref [11]). It carries the LP product-form method and its boundedness theorem to SOCP, where the dense low-rank part is always present when a large cone exists (p. 2). **Read**: partial. Read: abstract, §1, §3 opening (pp. 7–8), Table 1 and the work comparison (pp. 13–14), §4 opening, the §4.1 opening, Lemmas 1–3 (p. 17), the Theorem 1 statement and the start of its proof (pp. 19–20), Theorem 2 with the remarks after it (p. 22), §5 (pp. 23–24) and §6 (pp. 24–26). **Not read**: the §2 details (pp. 3–7), the §3 derivations of the update variants (pp. 8–13), the proofs of Lemmas 4–5 (pp. 18–19) and the rest of the Theorem 1 proof (pp. 20–21).

- **D1 Problem & entry**: In SOCP a large cone makes the normal-equations matrix dense, but it is a sparse matrix plus a low-rank dense matrix (p. 2). SMW updating is "not numerically stable on most SOCP problems (even randomly generated, nondegenerate problems)" (p. 2). Unlike LP, the dense part is always present when a large cone exists, and the matrix is badly scaled in the limit (p. 2). The analysis is harder than for LP. The updates contain subtractions as well as additions, and a third kind of eigenvalue stays O(1) (p. 3).
- **D2 Core idea**: Product-form LDLᵀ updates for V S Vᵀ with S an indefinite diagonal (p. 8). Five variants are derived from 1960s–70s updates (rank-1 Fletcher–Powell, rank-1 Bennett, rank-k Bennett, rank-k FP, block Bennett), with exact work counts (Table 1, p. 14). Rank-1 methods need the least work, and rank-k Bennett may win on parallel machines (p. 13). PFCF costs Θ(m²) against Θ(m^{5/2}) for full Cholesky when the cone sizes nᵢ ≈ √m (p. 14).
- **D3 Assumptions**: The iterates converge to a strictly complementary solution and stay in a central neighbourhood (p. 15). Formally, x(μ) = x* + O(μ) (Theorem 1, p. 19). The authors contrast this with LP, where any diagonal D works (pp. 14–15). The analysis is done for the primal case "for simplicity" (p. 17).
- **D4 Analysis (brief)**: The eigen-structure of the SOCP scaling matrix gives three rate classes of eigenvalues (§4.1, Table 2, pp. 15–16). Theorem 1 (entries of L bounded as μ → 0) reuses S050's smallest-bad-index contradiction (pp. 19–20). Theorem 2 extends boundedness to all product-form factors (p. 22). §5 builds a 3×3 trajectory off the central path on which L grows without bound, and names the lemma that fails (Lemma 4) (pp. 23–24). A bad example needs different convergence rates *within* one cone. Different rates *across* cones are still covered (p. 24).
- **D5 Experiments**: SeDuMi 1.04 (which already uses rank-1 FP PFCF) on 3 random problems and DIMACS SOCP problems (p. 24). Table 3 reports entry sizes: none exceeded 10,000. The exception is filtinf1, which has SDP blocks outside the theory (p. 25). A deliberately badly scaled variant is also reported (p. 25). Table 4 gives times with and without PFCF (p. 26). There is no SMW comparison because SeDuMi lacks it. The earlier LP finding (SMW about 2× faster) is cited instead (p. 26).
- **D8 Contribution & limits**: Algorithm variants, cost analysis and a boundedness theory. Limits stated: the theory needs the central neighbourhood (§5), does not cover SDP ("not applicable (at least not without major revision)", p. 25), and pivot skipping was never needed because SOCP IPMs stop earlier (p. 22). There is no conclusion section and no future work.

**Method links**:
- Method 2 ✅ evidence (p. 2, pp. 13–14): old update formulas (Bennett 1965, Fletcher–Powell) are kept and only their product form is new. The LP analysis is carried over and changed only where SOCP breaks it (pp. 14–15).
- Method 6 ✅ evidence (p. 2, p. 14): the sparse + low-rank structure of the normal equations is exploited, with the savings factor stated as a function of the cone sizes (p. 14).
- Research Taste mark 5 ✅ (pp. 23–24): the central-neighbourhood assumption is backed by an explicit example of unbounded growth, and the paper names the lemma that fails there.
- new-pattern candidate: extend own result to a harder class and list what breaks — additions vs subtractions, the extra O(1) eigenvalue class, and assumptions on the path (pp. 2–3, 14–15), with S050 as the base.

**Transferable techniques**:
- After proving a result under an assumption, build the smallest trajectory that violates it, point to the lemma that fails, and say which weaker version still holds ("different rates across cones", p. 24).
- Tabulate the exact operation counts of every algorithm variant (leading term plus the k-dependent term) and read off the regime where each wins (Table 1, pp. 13–14).
- When the host solver cannot run a competitor, say so and cite the measured ratio from earlier work rather than leaving the comparison out silently (p. 26).

**Quotes**:
- "Clearly, the rank-1 methods require the least amount of work." (p. 13)
- "On random problems, although there was less improvement, it was still substantial." (p. 26)

**Role**: supplement · **Coauthors**: L. Xie, D. Xu, S. Ebadollahi, S.-F. Chang, J. R. Smith (p. 1) · **Position in trajectory**: An IBM applied collaboration in video analysis. The two optimization components are EMD, which is a linear program, and multiple kernel learning, which is solved as an SOCP with SeDuMi (pp. 3–4). The paper does not say who contributed what. **Read**: full (5 pages). Figure 3 survives only as axis labels (p. 5).

- **D1 Problem & entry**: The task is to detect generic visual events (for example airplane taking off, riot) per shot in unconstrained broadcast news (p. 1). Shots are compared by the Earth Mover's Distance, computed by a linear program, and turned into a kernel exp(−d/A) for an SVM (pp. 2–3). (2) Cues are fused by multiple kernel learning. Kernel weights μⱼ are learned with support-vector weights shared across kernels, via Bach et al.'s dual (6), converted to an SOCP (pp. 3–4).

- **D4 Analysis (brief)**: None. The gain of EMD is explained by the sparsity of the LP's optimal flow, which stresses a few best frame matches (p. 4).

Future work: predict which fusion scheme suits which concept, and a single program that solves kernel and support-vector weights jointly (p. 5).

**Method links**:
- Methods 1–5: no link (applied ML paper with no oracle, DFO or complexity content).
- Method 6 ⚠ weak (pp. 3–4): a classical optimization model (LP transport, conic MKL) is used as a building block inside an ML pipeline. This is structure use, but not the black-box-structure lens of Method 6.
- Research Taste mark 6 (optimization and ML as one field) — context only. The paper does not state Scheinberg's role.

**Transferable techniques**:

**Quotes**:

### S102 · Rock physics and depositional history from seismic matching – a model study (69th EAGE Conference and Exhibition 2007, DOI 10.3997/2214-4609.201401654)
**Role**: supplement · **Coauthors**: S. A. Levin (Halliburton), U. Mello, V. Lopez, L. Xu, A. R. Conn, H. Zhang (IBM Research) (p. 1) · **Position in trajectory**: An IBM applied project. The group's own DFO code is one of the derivative-free solvers tested (p. 2). The paper does not say who contributed what. **Read**: full (5 pages). Figures 1–6 are not in the text. Only their captions and the prose about them were read.

- **D1 Problem & entry**: Infer the sedimentary and basin-model parameters that reproduce observed seismic data in both timing and amplitude. The inverse problem is ill-posed and computationally hard (p. 1). The problem is set up as a proof-of-concept model study. Basin2 was chosen because it is mature, freely available and fast enough for hundreds or thousands of optimizer calls (p. 1). The model has 26 parameters (p. 1).
- **D2 Core idea**: Wrap the forward chain Basin2 → petrophysics → seismic in an optimizer (p. 1, p. 3). Try derivative-free codes (DFO, NEWUOA, ASA) and gradient-based ones (IPOPT, CBB/CGCBB, LMDIF with finite-difference Jacobian) (p. 2). The least-squares misfit has many spurious local minima (Fig. 3, p. 3). The authors therefore (i) split the problem into a Basin2 loop and a seismic stage, "perhaps unnecessarily", (ii) switch to a smooth seismic functional (the envelope of the envelope of the trace), and (iii) add 20 empirical petrophysics coefficients as unknowns (p. 3).
- **D3 Assumptions**: None stated formally. The Basin2-loop functional F is a weighted sum of squares over pressure, shaliness, porosity, bulk density and depth (p. 3).
- **D4 Analysis (brief)**: None.
- **D5 Experiments**: Basin2-loop convergence of selected methods from several starting guesses (Fig. 5, p. 4; the figure is not in the text). A full-loop fit with ASA and NEWUOA, each needing "well over a thousand iterations" (p. 4). The measure is iterations, not function evaluations.
- **D8 Contribution & limits**: Feasibility of the machinery (p. 4). Next steps: a differential-semblance-type smooth functional, scaling and preconditioning, stochastic exploration of acceptable parameter sets, and field data (p. 4).

**Method links**:
- Method 5 ⚠ variant (p. 2, p. 4): many solvers are run on one application, but the reported measure is iterations, and there is no equal-accuracy protocol in the text.
- Method 6 ⚠ variant (p. 3): the misfit is a sum of squares, yet no residual-wise model is used. The only structure-aware baseline is LMDIF (Levenberg–Marquardt with FD Jacobian, p. 2). This is a missed-structure case, compared with Heuristic 3 of SKILL.md.
- new-pattern candidate: fix the objective, not the solver — when all solvers stall, plot the misfit on a two-parameter slice, diagnose spurious minima, and replace the misfit by a smoother functional (p. 3).

**Transferable techniques**:
- Before tuning optimizers on an inverse problem, plot the objective on a two-parameter slice. Many local minima mean the measure of fit is the problem (Fig. 3 caption, p. 3).
- Build a synthetic "ground truth" with the same forward model and fit it first, so that solver failures can be told apart from model error (pp. 1–2).

**Quotes**:
- "This told us we needed a smoother measure of seismic match." (p. 3)
- "Both the ASA and NEWUOA methods required well over a thousand iterations in order to achieve this degree of fit." (p. 4)
