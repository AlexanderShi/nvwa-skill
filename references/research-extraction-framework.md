# 研究Skill提炼方法论（Research Craft Extraction）

> 从顶尖研究者的论文、代码、方法论自述和学生回忆中，提炼**可执行的研究方法**。
> 研究模式下，Phase 1 读第二节（调研分工），Phase 2 读第三至八节（提炼），Phase 4 读第十一节（自检）。

---

## 〇、研究Skill vs 人物Skill

| 维度 | 人物Skill（`*-perspective`） | 研究Skill（`*-research-craft`） |
|------|---------------------------|------------------------------|
| 捕捉什么 | 怎么想、怎么说 | **怎么做研究**：选什么题、怎么设计实验、怎么判断结果、怎么写 |
| 核心单元 | 心智模型 | **研究方法**（可执行步骤）+ **研究品味**（判断标准） |
| 激活后做什么 | 以此人身份对话 | 用此人的方法处理用户的研究任务（选题评估、实验设计、诊断卡点、审读草稿），口吻可选 |
| 最重要的证据 | 言论 | **行为留痕**：论文结构、代码、消融实验、rebuttal、放弃的方向。自述方法必须和实际做法对照 |
| 验证方式 | 对已知问题立场一致 | 对已知研究判断一致 + 方法可执行 + 引用可核实 |

**关键区分**：捕捉的是 HOW they do research，不是 WHAT they discovered。蒸馏出来的Skill不是此人的论文综述——论文内容只作为「他怎么做研究」的证据。

## 一、研究能力的七层结构（提取目标）

| 层 | 要回答的问题 | 最可靠的证据来源 |
|----|------------|----------------|
| 1 研究品味 | 什么问题值得做？什么是好结果？什么是垃圾研究？ | 代表作共性、他明确拒绝的方向、他对他人工作的评价 |
| 2 选题 | 问题从哪来？怎么判断时机（why now）？什么时候放弃？ | 起源故事（口述）、研究轨迹中的转向 |
| 3 想法生成 | 灵感靠什么：跨领域迁移、反常现象、新工具、极致简化？ | 代表作解剖、访谈中的「那个想法是怎么来的」 |
| 4 实验与执行 | 怎么设计实验、选基线、做消融、调试、控制迭代速度？ | 代码仓库、论文附录、实验记录、学生回忆 |
| 5 结果判断 | 何时相信一个结果？何时止损？怎么对待负结果？ | rebuttal、撤回/勘误、放弃的项目、他批评别人的理由 |
| 6 表达 | 论文怎么组织？图怎么画？报告怎么讲？ | 论文本身（结构统计）、写作建议、演讲录像 |
| 7 研究组织 | 时间怎么分配？怎么带学生、怎么合作、怎么规划长期议程？ | 学生/合作者回忆、实验室指南、访谈 |

不是每位研究者七层都有证据。**没有证据的层就空着，在诚实边界里写明**，不要用通用建议填坑。

## 二、研究模式的6路调研（Phase 1）

### 任务分配

| Agent | 搜索目标 | 提取重点 | 输出文件 |
|-------|---------|---------|---------|
| 1 代表作 | Google Scholar / Semantic Scholar / DBLP / arXiv / OpenAlex，先跑 `scripts/fetch_publications.py` 拿发表全景 | 发表全景（方向分布、一作→末作的转变、合作网络、常投venue）；选3-5篇代表作做**代表作解剖**（见第五节） | `01-publications.md` |
| 2 方法论自述 | 「我怎么做研究」类文章/演讲、课程讲义、博客、推文串、PhD建议、获奖演讲、访谈中谈方法的片段 | 他**主张**的研究方法、品味判据、给学生的建议、反复出现≥3次的说法 | `02-methodology.md` |
| 3 过程证据 | GitHub仓库（代码结构、实验脚本、README）、论文附录与消融、OpenReview评审与rebuttal、实验记录、发现过程的口述、失败/放弃/被拒的项目 | 他**实际**怎么做：基线怎么选、先做什么后做什么、怎么调试、怎么回应质疑 | `03-process-evidence.md` |
| 4 学生与合作者 | 学生博客/回忆文章、博士论文致谢、实验室网站的lab guide或onboarding文档、合作者访谈、纪念文集、讣告 | 指导风格、组会习惯、实验室文化、**默会知识**（没写进论文但学生都知道的做法） | `04-mentorship.md` |
| 5 同行批评 | 复现失败、学术争论、公开审稿意见、批评文章、落空的预测、竞争学派的观点 | 他方法的盲区、适用边界、被证明错误的判断 | `05-peer-critique.md` |
| 6 研究轨迹 | 完整学术时间线、导师与学生谱系、研究方向转向及原因、**最近12个月**的新论文和新动向 | 转向的触发因素（新工具？新数据？失败？）、他进入/退出一个领域的时机 | `06-trajectory.md` |

**快速档**只跑 Agent 1-3（代表作+自述+过程证据）——这三路就能支撑「说的方法 vs 做的方法」对照，是研究Skill的最小可用集。

### 每个Agent的硬性要求（在人物Skill要求之上追加）

- **论文必须带可核实标识**：DOI / arXiv ID / 「venue + 年份 + 完整标题」三选一。禁止凭记忆写论文标题或结论——LLM最常见的幻觉就是编造引用
- **三类信息分开标**：「他主张的」（自述）/「他实际做的」（论文、代码、记录）/「别人观察到的」（学生、同行）
- **失败和放弃必须记录**：放弃的方向、被拒的论文、撤回的结论，信息量往往大于成功案例
- **标注时代与资源背景**：这个做法出现在什么算力/工具/团队规模条件下

### Agent prompt 模板（以 Agent 2 方法论自述为例）

```
你的任务：调研[研究者]公开阐述过的研究方法论。

搜索方向：
- 此人写过的「怎么做研究」类文章、博客、讲义、书中章节
- 演讲/获奖演讲/课程中谈研究方法的片段（优先找transcript或视频字幕）
- 访谈中被问到「你怎么选题」「这个想法怎么来的」「你怎么带学生」时的回答
- 推文串/短文中的研究建议
- 反复出现≥3次的研究主张（这些是真方法论，不是随口一说）

输出要求：
- 写入 [skill目录]/references/research/02-methodology.md
- 每条主张：原话（或忠实转述）+ 出处（URL/标题/日期）+ 可信度（一手/二手）
- 按七层结构归类：品味 / 选题 / 想法生成 / 实验 / 结果判断 / 表达 / 研究组织
- 如果此人的主张前后矛盾（早年说A、后来说B），两条都记录并标注时间
- 只记录他说了什么，不要在这一步判断他是否真的这么做（那是Agent 3的工作）

信息源黑名单：不使用知乎、微信公众号、百度百科。
```

Agent 3（过程证据）的prompt要额外强调：**找行为而不是找言论**——打开代码仓库看目录结构和实验脚本，打开论文看附录和消融表格的组织方式，打开OpenReview看他怎么回应审稿人。

### 学术信息源优先级

| 来源 | 揭示什么 | 权重 |
|------|---------|------|
| 用户提供的一手材料（论文PDF、讲义、组会记录） | 完整原文 | 最高+ |
| 本人论文正文与附录 | 实际研究行为 | 最高 |
| 本人代码仓库 | 实验习惯、工程纪律 | 最高 |
| 本人的方法论长文/讲义/演讲 | 主张的方法 | 最高 |
| OpenReview评审与rebuttal | 怎么回应质疑、坚持什么 | 高 |
| 学生/合作者的一手回忆 | 默会知识、指导风格 | 高 |
| 同行批评、复现报告 | 盲区与边界 | 中等 |
| 科普报道、二手转述 | 背景 | 低 |

## 三、研究方法的四重验证（Phase 2）

人物Skill用三重验证筛心智模型；研究Skill用**四重验证**筛研究方法，多出来的一重是「言行一致」：

| # | 验证 | 通过标准 | 例 |
|---|------|---------|----|
| 1 | 跨项目复现 | 在≥2个不同项目/论文/时期里体现 | 某人的多篇代表作都「先在玩具问题上跑通再放大」 |
| 2 | 言行一致 | 自述的方法（Agent 2）在实际产出（Agent 3：论文结构、代码、实验设计）里找得到证据 | 他说「先建立简单基线」→ 他的论文里确实有强基线和逐步加复杂度的消融 |
| 3 | 可执行 | 能写成「步骤1/2/3」，且执行后产生的行动**不同于通用做法** | 「多读论文」不可执行；「只读摘要和图，挑出3篇结果反直觉的精读」可执行 |
| 4 | 排他性 | 不是所有好研究者都这样做 | 「做重要的问题」太通用；Hamming的「Great Thoughts Time」（每周五午饭后只讨论领域里的大问题）有区分度 |

**分级处理**：

- 四重全过 → **核心研究方法**（3-7个）
- 可执行 + 另过至少1重 → **研究启发式**（5-10条）
- 只有自述、找不到实践证据 → 放进「主张但未验证」清单，写进诚实边界，**不进核心方法**
- 不可执行 → 丢弃（哪怕是名言）

## 四、研究品味提取

品味是最难蒸馏、也最值钱的部分。从四个角度夹逼：

1. **正向选择**：代表作的共性是什么？（问题规模、可验证性、结果是否简洁、是否开辟新方向）
2. **负向选择**：他明确拒绝、放弃、批评过的方向——「我不做X，因为……」比「我做Y」信息量大得多
3. **评价他人**：他推荐的论文、称赞的工作、公开的审稿意见和批评 → 反推他的好坏标准
4. **时机**：他在什么时候进入/退出一个方向？早于共识还是晚于共识？进入时什么条件刚刚成熟？

**输出格式**：

- **品味判据**（5-8条）：「好研究是……」「坏研究的信号是……」，每条附≥2处证据
- **品味速测题**（5-8个是/否问题）：由判据转化而来，生成的Skill用它来评估用户的选题
- **品味预测题**（留给Phase 4）：列出此人真实面对过的几个候选方向（他做了哪个、放弃了哪个有公开记录），测试Skill能否预测他的选择

## 五、代表作解剖

选3-5篇：最高被引 + 本人自认最重要 + 研究方向的转折点之作。`fetch_publications.py` 输出的「代表作候选」可作为起点，但最终由调研判断。

每篇按下表解剖：

| 维度 | 要回答的问题 | 证据要求 |
|------|------------|---------|
| 起源 | 这个问题从哪来？ | 本人口述 > 合作者回忆 > 推测（推测必须标注） |
| 为什么是那时 | 当时什么条件刚刚成熟（算力/数据/工具/理论）？ | 可推断，需说明依据 |
| 关键洞察 | 一句话 | 论文本身 |
| 最小证据 | 第一个让他相信「这条路走得通」的实验或推导是什么？ | 论文/口述 |
| 放弃的路 | 过程中试过又放弃的方案 | 附录、口述、早期版本（arXiv v1 vs 终版） |
| 接受过程 | 被拒？被忽视？多久被认可？ | 公开记录 |
| 体现的方法 | 对应哪个核心研究方法（交叉索引） | — |

**规则**：每个核心研究方法至少被1篇代表作解剖佐证；「起源」「放弃的路」没有一手来源时必须写「推测」。

## 六、研究工作流重建

把研究方法组装成按阶段执行的工作流。阶段参考：选题 → 文献 → 想法 → 实验设计 → 执行与调试 → 结果判断 → 写作 → 发表后。

每个有证据的阶段写清：

- **输入**：用户需要提供什么（想法描述、实验日志、草稿……）
- **步骤**：此人特有的做法，逐步写
- **🔴 检查点**：什么情况下停下来、回退或止损
- **产出**：输出给用户的格式
- **与通用做法的区别**：一句话说明为什么这是「X式」而不是教科书

**没有证据的阶段**：不写X式工作流，在Skill里写明「[研究者]在此阶段没有可蒸馏的公开方法」，需要时给通用做法并明确标注「非X式」。宁缺毋滥。

## 七、时代性、领域性与资源门槛过滤

研究方法比思维框架更容易「过期」和「水土不服」。每个方法都要过一遍：

| 过滤 | 问题 | 处理 |
|------|------|------|
| 时代绑定 | 这个做法依赖当年的算力/工具/数据条件吗？ | 标注「时代性」，并给出今天的等价做法 |
| 领域绑定 | 只适用于理论/实验/湿实验/系统/某个子领域？ | 区分「领域通用」与「领域专用」，结合Phase 0A确认的用户领域标注是否需要转译 |
| 资源门槛 | 需要大实验室、大算力、大团队才能执行？ | 标注门槛，给出小资源版本或明确说「个人研究者不适用」 |
| 地位依赖 | 只有成名后才能这么做（如只做高风险长期题）？ | 标注「资深者策略」，给出职业早期的调整版本 |

## 八、默会知识与诚实边界

研究能力很大一部分是默会的：看一眼loss曲线就知道哪里不对、听一句想法就知道值不值得做。

- **能蒸馏的**：写下来的（论文、讲义、建议）和做出来留痕的（代码、实验设计、回应审稿）
- **部分能蒸馏的**：学生转述的默会知识 → 标注「据学生回忆」，置信度中
- **蒸馏不了的**：实时的手感和直觉、没有留痕的组会讨论、未公开的失败

研究Skill的诚实边界至少包括：默会知识缺口、时代/资源差异、领域边界、「主张但未验证」的方法清单、调研时间。

## 九、研究诚信红线（生成的Skill必须内置）

1. **不编造引用**：Skill提到具体论文前，必须用工具核实标题、作者、年份、venue；核实不了就说「我记得有相关工作，但未核实，请自行检索」
2. **不编造数据**：不生成虚构的实验结果、统计量、benchmark分数
3. **不替代把关者**：不替代同行评审、导师判断、伦理审查（IRB等）
4. **不协助学术不端**：数据造假、p-hacking、选择性报告、隐瞒负结果、违反目标venue的AI使用政策——如此人公开反对过这些做法，引用其原话作为拒绝理由

## 十、多研究者研究Skill（主题 × 研究）

输入是「ML研究方法论」「理论物理怎么做研究」这类主题时，结合主题Skill变体：

- 先选3-5位该领域公认的顶尖研究者或方法论作者，每人分配1-2个Agent（优先Agent 2自述 + Agent 3过程证据）
- 提取**共识方法**（多人都这么做）+ **分歧**（A主张深耕一个问题十年，B主张每两年换方向）
- 每条方法标注归属，分歧并列呈现，让用户按自己的处境选
- 不模拟任何个人口吻

## 十二、全文深读（可选的深度档加强）

搜索摘要只能支撑「他说过什么」；要看清「他实际怎么做」，最终要读论文全文。

1. **发表列表**。有两种来源：
   - 用抓取工具（WebFetch 等）逐页读 Google Scholar 个人主页。Scholar 没有 API，也拦 curl。
   - 或跑 `python3 scripts/fetch_publications.py "<姓名>" --json --out <skill目录>/references/sources/publications`（OpenAlex）。

   列表要用 DBLP（REST 被拦时走 SPARQL 端点）、Crossref、arXiv 交叉核对，去重后写成 `publications/works.json` + `scholar.md`。
2. **开放全文**：`python3 scripts/acquire_fulltexts.py <skill目录>`
   - 依次尝试 arXiv（按 ID 或标题检索）、Unpaywall 开放获取、works.json 里的作者或仓库链接。
   - 校验下载的 PDF 确实是这篇论文。扫描件或乱码文字层自动用 tesseract 做 OCR。
   - 生成 `references/sources/papers/INDEX.md`。
   - PDF 与 `txt/` 不提交，新克隆的仓库里没有。本地没有文件的行会保留 INDEX 里已提交的 txt/pdf 状态，但重新抽取文本和第6步的摘录核对都需要原文件，所以要在存有原 PDF 和 `txt/` 的那份工作区里跑。旧版脚本会把这些行重置为 `no-oa`，遇到时用 `git checkout -- <skill目录>/references/sources/papers/INDEX.md` 恢复。
   - OpenAlex 与 export.arxiv.org 可达时，旧的 `fetch_fulltexts.py` 也能用。
3. **agent 补搜**：仍标 `no-oa` 的论文，由 agent 在合法的开放来源里找，比如作者主页、机构技术报告、Optimization Online、HAL、会议官网、OSTI、CORE。
   - 找到的文件命名为 `<ID>-<年份>-<标题前8词>.pdf`，存进 `papers/`，再重跑第2步。
   - 不用 Sci-Hub，不绕付费墙。
4. **切批**：`python3 scripts/plan_reading_batches.py <skill目录> [--round N --exclude /tmp/上一轮.json] > /tmp/batches.json`（批次JSON放在仓库外）
   - 定角色：core / supplement。skip 不由它判断：专利、talk 由第2步按 kind 设定，非本人作品用 `--skip-ids` 或手改 INDEX 的 Role 列。
   - 按页数切批：core 精读，supplement 略读，book 按章读，abstract 只写摘要级卡片。
5. **写卡片**：一批交给一个 agent，按 `references/paper-reading-card.md` 写 `references/research/cards/<批次>.md` 和 `<批次>.digest.json`。`07-paper-cards.md` 做索引，每张卡片按 digest 字段手写一行（仓库里没有生成脚本）。
6. **核对摘录**：`python3 scripts/verify_card_quotes.py <skill目录>`。全部逐字通过才往下走。
7. **回填阅读状态**：`python3 scripts/mark_read_from_cards.py <skill目录>`。
8. **汇总**：按卡片模板第三节的保守更新规则，先写 `08-deep-reading-synthesis.md`，再改 SKILL.md。
   - DFO 团队的流程是：汇总提案 → 保守修改 → 三个只读质疑者复核 → 修正。
   - 改完重跑 `quality_check.py`。

## 十一、质量自检清单（研究Skill）

生成后逐项检查（`scripts/quality_check.py` 会自动识别研究Skill并跑对应检查）：

### 研究方法
- [ ] 3-7个核心方法，每个都过了四重验证？
- [ ] 每个方法有「操作步骤」，且步骤不同于教科书通用做法？
- [ ] 每个方法标注了言行一致性（✅ 自述+实践 / ⚠️ 仅自述）？
- [ ] 每个方法标注了局限（时代/领域/资源门槛）？

### 研究品味
- [ ] 有品味判据（好/坏各有），每条≥2处证据？
- [ ] 有可直接用于评估选题的品味速测题？

### 工作流与证据
- [ ] ≥3个阶段工作流，每个有检查点？
- [ ] 无证据的阶段已标注，没有用通用建议冒充？
- [ ] ≥2篇代表作解剖，推测部分已标注？
- [ ] 所有引用的论文都有DOI/arXiv ID/venue+年份，可核实？

### 诚信与边界
- [ ] 研究诚信规则完整保留（不编造引用/数据、不替代同行评审）？
- [ ] 诚实边界≥3条，含默会知识缺口和「主张但未验证」清单？
- [ ] 至少2对内在张力（如深耕 vs 转向、简洁 vs 规模、说的 vs 做的）？

### 整体
- [ ] 拿一个真实卡住的研究问题去问，输出是可执行的下一步，而不是鼓励和空话？
- [ ] 删掉名字后，能看出这是谁的研究方法？
- [ ] 读完Skill的人学到的是「怎么做研究」，而不是「他发现了什么」？
